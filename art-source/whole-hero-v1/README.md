# 固定整身主角 v1

> 历史批次：2026-10-21已由[粗像素Q版主角](../chibi-runtime-v1/README.md)替代。下文保留当时的生产与验证记录，不作为当前运行资源路径。

2026-10-20：用户取消分部件角色与装备改变人物贴图。此批次替代 `rekindled-runtime-v1` 的十部件骨架；旧文件仅留制作历史，不再由角色加载。身份沿用[主角03](../rekindled-hero-v3/README.md)：死亡细胞取向，无发、无血、无五官阴影脸，灰白尸肤、简朴暗色裹衣与小余火。没有固定职业或购买装备叠层。

当前每帧为一张完整身体，肩、肘、髋、膝、衣服在图内一起绘制。战场、主菜单与商店使用同一个 `HeroSprite`；商人暂复用人物加独立柜台。装备仍有六栏、属性和被动，图片仅作商品图标；普攻形式由余烬决定。

## 素材与帧序

| 文件 | 内容（每个方向） | 播放 |
| --- | --- | --- |
| run.png | 八帧跑动 | 20 FPS循环 |
| walk.png | 八帧慢速移动 | 12 FPS循环 |
| melee.png | 八帧蓄力、挥臂、回收 | 18 FPS单次 |
| ranged.png | 八帧准备、释放、回收；施法复用 | 18 FPS单次 |
| states.png | 0–1待机、2受击、3–7倒地 | 2 / 8 / 8 FPS，只有待机循环 |

每张1536×1024 RGBA、8列×5行，依次为 S、SE、E、NE、N；NW/W/SW整张镜像，不单独翻转肢体。共200格整身姿势，不是200格独立手绘高精度动画或60 FPS序列。

`*.prompt.txt`保存实际调用文本，`generation.json`记录工具输出文件。使用内置image_gen；run以concept.png提供身份，其余以run.png提供身份和布局。运行PNG是工具输出的原样副本；未用脚本抠图、重绘、插帧或调整像素。完整生成图中查看器可能显示透明像素的隐藏RGB，实际透明面积约54%–64%；不能据暗底截图推断不透明背景。

## 空间与接入

- 定义：`atlas-definitions.json`；量测：`alignment.json`。
- `rect`为源PNG左上角坐标，透明间隙实测切分；生成请求的等格不作为事实。
- 全动作固定scale=.38，站立体高约72设计像素；实际镜头zoom1.25。不同帧不归一化到同一个包围盒。
- 每个方向共用地面Y基准；列原点以记录的规则排列，允许本体在攻击、腾空、倒地时相对原点移动。anchor从裁切图左下角归一化计，不逐帧锁最低不透明点。
- `art-source/art-completion-v2/manifest.json`引用定义，`scripts/inspect-pixel-art.py`生成`content/pixel-art.ts`。修改来源后重新生成与`--check`，不要直接改生成表。
- `HERO_CLIPS / wholeHeroFrame`仅选择表现帧，`HeroSprite`只接收MotionPose；没有装备输入或分段旋转。模拟决定命中 / 位移，暂停冻结。
- 死亡五帧在 .5秒到达末帧，.65秒后淡出，1.2秒回收并显示失败面板；等待期间战斗已结束。怪物保持原.9秒生命周期。
- Creator 3.8.8已生成PNG与TS的真实.meta；运行资源位于`EmberDemo/assets/resources/art/whole-hero-v1/`。

## 质量边界

这是整身方案的首版运行素材：消除运行时关节拼接，但AI帧间的手形、衣褶和步态仍有差异，慢走与跑步的步幅区分还可加强。源图细节、色数、分数alpha与非整数texel显示尚未达到严格低分辨率像素成品标准，继续由ART-08精修。完整身体不等于已经完成最终动画打磨；不以张数或FPS替代实际运动检查。

本轮验证与截图见[验证记录](verification.md)，专项入口 `node scripts/browser-whole-hero.mjs`。旧装备八方向补图任务已取消；新装备只制作UI图标。
