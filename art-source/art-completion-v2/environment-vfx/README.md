# Environment and VFX completion batch

Uses the built-in image_gen tool; original RGBA files are copied unchanged. Python is used only for alpha / layout measurement, never image editing.

Audit: the existing `pixel-v1/environment.png` provides nine warm stone / foliage props and both maps reuse it. `skills.png` and `perks.png` are UI icons, not temporal VFX frames. Actual projectile cores, hit contours and effects were Graphics paths. The new frost props have independent frozen architecture / foliage / crest silhouettes. The new VFX atlas is a decorative flipbook; collision, damage and danger contours still come from the simulation snapshot.

Runtime IDs: `environment-frost-v2` (nine props in the same semantic order as the courtyard atlas), `vfx-bursts-v2` (row-major four frames each: fire, ice, physical right-facing slash, hollow shield). Registration / Creator import are integrated by the parent agent.

`PixelVfxView` uses snapshot cue age (four frames at .1 seconds, .4-second lifetime), so pause freezes poses, cue removal / restart clears all retained nodes, and map changes do not introduce a wall clock. At most 24 visible decorative nodes are lazily allocated and then reused; offscreen / enemy / arc / number cues allocate none. Real projectile cores and dangerous shapes have no decorative budget limit. This does not claim GPU performance measurements or four-player readability verification.

The atlas adds fire/ice bursts, physical slashes and shields; Graphics still supplies projectile travel, lightning, healing, zones, enemy boundaries and other effect families. No claim is made that every skill / perk has a bespoke animation.

Verification: `pnpm typecheck:cocos` passed before atlas registration. Creator / browser verification must be performed after the parent agent registers/imports final assets. Source atlas previews alone do not prove in-game timing or performance.

## Cue audit and scheduling verification

`SkillSystem` emits a real shield cue for both `shield` (default W) and `ironGuard`; this reaches the hollow shield row. `CombatEngine.shield` itself does not emit a visual cue, so reactive equipment shields retain their existing Graphics shield indicator. Fire nova and frostNova emit `explosion` with `fire` / `ice`, cleave emits `swing` with `fire` appearance; the swing kind selects the slash row before element mapping, and Earthwake emits `quake` with its appearance. Unsupported mist / heal / arc / generic cast cues do not borrow a gold slash. Projectile impact only produces damage cues today, so fire/ice impact decoration is not claimed for every projectile.

`PixelVfxPlan.ts` is independent of Cocos and wall clocks. It schedules shield feedback ahead of bursts/slashes and generic quake decorations, then newer cues ahead of older same-priority cues. It drops offscreen and expired candidates before applying the 24-instance budget. To protect danger information when 20 effects overlap, it projects both outer and inner danger contours using the actual 54×28 projection, then omits any decorative sprite whose conservative bounding circle approaches those edges. It never removes the warning itself. This can deliberately remove a shield or explosion near a danger edge; its original Graphics indicator remains.

`pnpm exec vitest run tests/pixel-vfx.test.ts` passed 5 tests (including the real cleave mapping): an actual default W produces shield row feedback; unchanged snapshots retain the same pose and expired/reset cues disappear; a new shield survives 40 old explosions regardless of input order with 24 selected; unsupported/offscreen cues are culled and frost stays frost; 20 overlapping bursts on a real projected ring edge are omitted while distant bursts remain. `pnpm typecheck:cocos` passed after this extraction. These tests verify scheduling and geometry, not rendered GPU performance.

Final browser checks after Creator import/build: cast W and ironGuard at ordinary speed and pause on a frame; observe both hollow shield phases and freezing. Cast nova / frostNova / cleave to distinguish families. At a boss ring or lane, overlap 20 friendly cues on the danger edge and verify the texture layer yields while both ring boundaries / lane directions remain intact.
