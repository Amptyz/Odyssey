# 战斗平面、速度与镜头

2026-10-20 的 FEEL-03 将地面改为**等比例战斗平面**。世界坐标使用欧氏距离，显示只做45°旋转 / 坐标轴翻转、统一缩放和平移；不压缩纵深，也不按方向增加移速。人物、建筑的侧面贴图与前后遮挡继续表达立体感。

## 唯一距离契约

- 一格在任意世界方向长度相同；普通移动、冲刺、弹体、射程、碰撞、寻路、交互和 AI 可逃离性评估使用同一套世界单位。
- `utils/GroundPlane.ts` 提供单位正交基变换：`viewX = (x-y)/√2`、`viewY = -(x+y)/√2`，向量长度不变。主角方向与 WASD 共用此基，不另写宽高比。
- `render/GroundProjection.ts` 将 view 坐标乘以 `pixelsPerUnit × zoom` 再加 origin，提供对应逆变换和 `worldLengthToScreen`。Projection 只有一个比例，不提供独立的横 / 纵缩放。
- `worldMoveSpeed / stats.speed` 表示真实的世界格/秒；无遮挡、满输入、匀速时 `|velocity|` 与它一致。模拟输入幅度、减速、起步 / 刹停、碰撞会降低实际速度，方向不会。
- 判定由 CollisionWorld / Pathfinder 与模拟时间负责，不能从像素、骨骼、动画或屏幕圈反推伤害。相机参数不参与战斗公式。

旧的 `GroundMovement` 方向补偿及其 `.meta` 已删除。`IsoProjection.ts` 重命名为 `GroundProjection.ts` 并保留原 UUID；不要恢复双轴压缩或在移动中加显示修正。

## 参数入口

统一入口：`EmberDemo/assets/scripts/ember/content/tuning.ts`。修改后运行检查并重新构建 Creator Web Desktop。

| 参数 | 当前值 | 作用 |
| --- | ---: | --- |
| GROUND_VIEW.pixelsPerUnit | 54/√2，约38.184 | 每格对应的设计像素，两个方向共用；保留旧版横向画面尺度 |
| moveSpeedMultiplier | 1.5 | 全单位普通移速的统一倍率，在速度点换算处应用一次 |
| projectileSpeedMultiplier | 1.5 | 普攻、技能、余烬和敌方弹体的统一倍率 |
| cameraZoom | 1.25 | 地面、单位、道具、交互物与装饰特效同步缩放；HUD保持原大小 |
| cameraFollowHalfLife | 0.1秒 | 镜头每0.1秒收敛一半剩余距离 |
| cameraSnapDistance | 12格 | 大跨度传送直接定位；新场景、重开和恢复也直接定位 |

`MOVE_SPEED_SCALE = .01 × moveSpeedMultiplier`。玩家 rawMS421.25 经软阈值为420点，实际6.3格/秒；苔刃精灵4.68、霜足跳兽5.94格/秒。当前 zoom 下玩家任何方向均约300.7设计像素/秒，纵向不再实际走12.15格/秒。固定单位仍用canMove:false；速度点软阈值与减速叠加不变。

WASD按屏幕方向反旋转并归一化，双键斜走不加速；右键路径按真实世界距离加速 / 刹停及停止。敌人普通追逐、退避与返巢使用同一实际速度；AI 的可逃离性评估也只计算真实可走距离。

冲刺按技能自己的世界距离 / 时长执行，不乘普通移速倍率。所有弹体生成时调用 `projectileSpeed(base)` 一次，用实际速度计算存活时间 `range / speed`；倍率不改变射程或伤害。现在它们的屏幕速度和长度也不再依方向压缩，连续扫掠碰撞、最终不足一帧的飞行和墙体遮挡继续生效。

## 地图、范围与输入

两张地图的尺寸、障碍、群组、起终点与导航坐标保持原有世界定义；新的画面沿纵深展开，屏幕一次显示的地面范围会变化。EnvironmentView仍按逆投影视口裁剪地砖和道具，地图不缩小到一屏。

圆 / 环在屏幕上保持圆 / 环，扇形保留角度，胶囊保留等宽；预警与技能反馈仍投影真实 HitShape / ShapeContours。F3碰撞圈与出口范围使用同一个长度换算，出口圈包含zoom。脚下标记、准星与目的地提示同步采用圆形。角色阴影、身体护盾外壳属于装饰，允许椭圆，不表示碰撞范围。

小地图通过 `minimapProjection` 使用与主战场相同的方向和等比例距离，再将旋转后的地图边界装入UI矩形；右移、向上等方向不再在小地图另转一次。

立体人物 / 怪物 / 柱子的贴图比例保持；旧地面徽纹在运行时将原压缩的脚下平面展开为等宽高覆盖，不改PNG像素，也不修改实体碰撞。旧位图中预绘的斜面仍有美术局限，后续重制按新地面契约制作。

每帧先准备一次平滑Projection，InputController用它反投影鼠标，ArenaView用同一对象绘制；不能在绘制阶段再次推进镜头。实际屏幕 / CSS / DPR的转换仍由输入边界处理。主角八方向通过正交基选择贴图，动画速度读取真实世界速度，不含镜头比例。

## 存档、联机与镜头

RunCheckpoint仍为v4：坐标、朝向、装备、余烬与关卡ID的含义不变，不转换旧坐标；恢复时按新镜头定位。存档未保存旧投影宽高、路径速度或任意战斗中间帧，所以无需迁移格式。恢复后的运行采用新移动规则，不保证重放旧版战斗结果。

联机命令继续携带世界坐标或归一化方向，房主统一计算；各客户端使用相同版本投影显示，不能混用旧、新客户端来判断手感。

SmoothCameraFollow在世界空间做指数跟随，响应不依赖渲染FPS；玩家移动时可以略离中心，停下后收敛。暂停保持镜头，切场景 / 重开 / 恢复直接定位。

## 背景：为什么不能只用移速补偿

正交投影消除随远近缩小，不消除倾斜地面的方向压缩。参见 [Unity相机说明](https://docs.unity3d.com/Manual/CamerasOverview.html) 与 [Autodesk正交投影说明](https://help.autodesk.com/cloudhelp/2015/ENU/SimMech/files/GUID-0EE952D9-FE10-40A4-B24A-1C9ED0D3CFDC.htm)。旧54×28投影将纵向压为横向约52%，FEEL-02通过增加纵向世界速度维持屏幕等速，导致穿越世界圆形范围时方向不公平。

本版选择等比例地面与侧视贴图组合：保留立体外观，消除地面度量冲突。这个选择不依赖“英雄联盟全部模型倾斜45°”等未经验证的说法。

## 验证

- `pnpm check`：投影任意方向 / 位置 / zoom的长度与垂直性、逆投影、实际圆 / 环轮廓、小地图；八方向玩家 / 敌人的世界与屏幕双重等速，路径刹停、减速、模拟量、碰撞、危险圈逃离、存档与两玩家隔离；真实弹体与冲刺的世界 / 屏幕长度及固定步进。
- Creator构建后 `pnpm test:movement`：真实WASD组合键和右键，分别测量世界位移与像素位移，抵消镜头跟随；不只检查屏幕等速。
- `pnpm test:feel`：镜头滞后 / 收敛、移动中准星、实体缩放、新世界定位与敌弹。
- `pnpm test:hitboxes`、`pnpm test:scenes`：实际鼠标指向、命中体积、交互、两图休息点与商人；`pnpm test:multiplayer` 检查房主权威、双玩家与恢复。

以上是验证入口，实际本次结果与截图另见实现记录和 reports/ground-plane。
