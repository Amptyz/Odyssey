# 单人保存与读取

普通单人试炼和实验局使用一个浏览器本地进度槽。首页点击「继续存档」；游戏中按 Esc，在暂停菜单点击「保存进度」或「读取存档」。失败 / 通关页面也可读档。首页和暂停菜单均可导入、导出 JSON 存档文件。

开始新游戏会覆盖该槽；「重新开始」回到首页时先保留原存档，直到再次开始新游戏；读取后重开沿用存档的随机种子。需要保留多个进度时，先导出文件备份。浏览器本地进度按当前网址保存，换浏览器 / 端口 / 设备时通过文件导入转移。

## 保存规则

- 自动保存发生在启程、打开 / 关闭交互、选择奖励、确认技能、交易、出发、清场和通关等稳定边界。刷新或关闭页面时也会尝试保存。
- 营地 / 休息点 / 清场阶段，手动保存可记录当前位置；技能空槽、装备、库存、金币、余烬、领取记录、当前商店 / 奖励面板和待确认技能都保存。
- 战斗保存的是本关起点；读档重建该关敌人，重置本关战斗进展，保留进入本关时的构筑和资源。读取战斗存档后保持暂停，按 Esc 或点「继续试炼」再行动。
- 读取必须在首页、暂停或结算界面操作。读档先验证并构造新世界，再替换当前世界；无效文件不修改当前游戏，也不覆盖旧存档。
- F2 测试世界不写入普通存档；测试配置继续使用开发者预设。联机仍走原房间码与中转保存，本地按钮不会向房主发送单人存取命令。
- 本地存储不可用 / 空间不足时显示失败，可继续导出当前恢复点。成功读取文件但无法写入浏览器时，仍可玩该进度，并提示保留文件。

## 代码入口与格式

| 入口 | 职责 |
| --- | --- |
| `platform/RunSaveStorage.ts` | 存储键、文件封套、校验、地点摘要 |
| `platform/LocalTransport.ts` | 自动落盘、SaveRun / LoadRun、读档原子替换、开发者隔离 |
| `platform/RunSaveFiles.ts` | 原生文件选择、下载、页面离开时保存 |
| `simulation/RunCheckpoint.ts` / `GameWorld.ts` | v4 稳定恢复点及世界恢复，非完整战斗快照 |
| `render/MainMenuLayout.ts` / `Hud.ts` | 继续存档、暂停存取、文件入口和状态反馈 |

以上源码路径相对于 `EmberDemo/assets/scripts/ember/`。

本地键为 `ember.solo.run.v1`，文件格式为 `{format:'ember-solo-save',version:1,savedAt,checkpoint}`，其中 checkpoint 为 v5 恢复点。也接受原始 v4/v5 恢复点和只有一名 hero 的历史房间备份。多人文件提示使用原联机房间码，不丢弃队友数据后伪装为单人。

文件上限 2 MB；拒绝不支持的版本、缺失 / 重复技能槽、无效内容引用及损坏的数据。本地时间戳只用于存档元数据，不参与游戏随机与模拟时间。
