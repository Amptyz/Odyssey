本次将既有两张地图各组织为5关。游戏仍是同一个Cocos工程；关卡共用各地图的静态逻辑障碍，每关使用独立起点、出口、建议路线与固定敌群。不会把整个地图缩到一屏。

## 清怪与出口

每关入口重新确定队伍出发位置，四人以0.9格间距的小方阵出生。清场进入cleared并结算一次金币，倒地队友复起；全队继续走到指定出口集合，由房主按F确认进入下一段旅程。出口为1.8格半径，地面圈由灰色转为青绿色。

多人出发条件：所有活跃玩家中心都在出口半径内、没有打开交互面板，再由房主按F确认。清场后倒地者复起并参与集合；明确跳过的离线玩家不阻塞出口。全队在战斗中倒下仍然失败。尚有敌人存活时，即使全队走到出口也不能完成。

余烬与商店由content/scenes.ts的JOURNEYS配置：两图均在第2/4关后进入休息点，第1/3/5关有清场余烬。开发者清怪工具仍只用于测试，不直接发放击杀或出口完成奖励。

## 数据与接线

`content/maps.ts`保留waves以兼容关卡计数与内容目录，每张图长度为5。每关的level包含：

```ts
{
  id, name, subtitle, // name 必填，subtitle 可选
  start: {x,y},
  exit: {x,y,radius},
  route: [{x,y}, ...],
  groups: [{id, center:{x,y}, radius, spawns:[{enemyId,count}]}],
}
```

waves.spawns是groups的确定汇总，用于内容校验/统计；实际布置使用groups，不再在大广场随机四周刷怪。hpScale本批均为1，怪物属性由新模板决定。新增关卡可以复用同一地形，改变入口、出口、路线与敌群；需要独立障碍的关卡应先显式扩展导航生命周期，不能仅让表现偷偷换墙。

`simulation/LevelSystem.ts`不依赖cc或真实时钟，提供：

- `levelDefinition(map,wave)`：取关卡共享定义；波次按1起算。
- `levelSpawn(map,wave,playerIndex)`：返回独立出生位置对象。
- `enemyPlacements(map,wave)`：稳定的enemyId/at/groupId/hpScale列表，不消费战斗或奖励随机流。GameWorld使用实际半径导航确认后创建单位。
- `exitProgress(map,wave,participants,remainingEnemies)`：纯函数判定出口是否开放、谁需要进入、谁已进入和能否完成。participant为{id,active,alive,x,y}。
- `levelSnapshot(...)`：复制出口、路线等展示数据，包含remainingEnemies/exitActive/requiredIds/insideIds。

关卡恢复仍保存波次起点而不是任意战斗帧。地图ID与wave重建入口/出口/布局，展示level快照不能作为恢复存档。房间快照必须以操作者对应的hero为本地观察对象。

## 镜头、输入与表现

`IsoProjection.followProjection`将本地玩家插值后的脚底固定到设计屏幕中心(0,0)，zoom恒为1；不在地图边缘解除锁定，也不随着地图扩大缩小战斗单位。`worldToScreen`和`screenToWorld`共享同一份Projection。

`GameBootstrap.draw`先调用`ArenaView.prepareCamera`，再更新输入，最后绘制ArenaView。这样鼠标地面指针与画面使用同一帧相机原点，移动镜头不会造成瞄准偏移。网络客机使用snapshot.hero，自然跟随自己的角色。

`LevelGuidanceView`提供当前关名/清怪任务、出口集合人数、最近残敌或出口方向箭头，以及带路线、障碍、玩家、存活敌人、出口的小地图。小地图仅用于导航，不改变实际游戏缩放。

EnvironmentView只绘视口覆盖的4×4低对比石板，场景装饰按视野懒创建并隐藏离屏节点；大图边界植物每8格稀疏摆放。地图底色/水边只使用少量多边形，不逐格绘制整张大地图。ArenaView对单位视野裁剪，并保留池化节点/脚底深度排序。

敌人使用MonsterVisual的17种程序化轮廓与统一动作，状态来自EnemySystem快照；drawEnemyWarnings使用相同Projection绘制预警和敌方弹体，避免恢复旧两种敌人的硬编码预警。

## 验证

`pnpm exec vitest run tests/levels.test.ts`通过10项测试，覆盖两图10关路线可达、四人出生位置、固定敌群确定性/安全、Boss净空、清怪与多人出口边界、复制隔离、跟随投影反投影及视口随本地角色移动。真实GameWorld集成覆盖两图5关完整阶段推进、清怪后等待出口、第5关对应Boss、多人生还参与者集合与波次恢复后重建起点方阵/敌群。

最终逻辑验证执行`pnpm check`，详细测试数量以本次最终输出和总验证报告为准，避免文档中的固定数字过期。

`pnpm exec tsx scripts/campaign-playthrough.ts`使用正常GameWorld命令，不修改生命/伤害/冷却、不启用开发者选项，按正常购买、奖励、移动、攻击、技能及出口规则跑两图完整五关。最终胜负、耗时、生命、构筑和导航诊断见`reports/campaign-playthrough.json`。这是能读取预警并自动躲避的输入机器人验证，不等于普通玩家难度结论。

`node --import tsx scripts/browser-levels.ts`使用真实键鼠验证跟随镜头、准星反投影、同类双武器购买、自然清怪→出口→奖励，以及单独F2两图第5关Boss视觉；结果与截图引用见`reports/browser-levels.json`。另以`EMBER_LEVEL_SCOPE=normal-nav`运行正常第一关与贴柱导航专项：在显式F2隔离场景用实际WASD抵达合法碰撞边缘，再切经典右键点击离开，验证导航与移动半径一致，报告为`reports/browser-levels-navigation.json`。开发者隔离场景不混作正常战斗通关证据。

人工画面检查包含正常战斗、出口开启、两Boss、六栏同类双武器和缩放窗口；最终production构建确认Stats框隐藏、近邻起点纹章已去重。最新构建后的执行状态以报告时间与总验证记录为准。

旧测试若假定20×20地图、自动清怪领奖、原波数或旧敌人数量，需要按本次明确的新规则迁移，不能改地图尺寸或恢复自动结算去迎合旧断言。
