# 像素特效制作与验收

本文是 [美术风格](ART_DIRECTION.md) 的特效细则。2026-10-20起整体基调为黑暗、血腥但清晰可读的像素奇幻，形态、节奏与预算规则继续适用；旧明亮自然方向不再作为默认。血迹用低对比暗红成块表达，短促飞溅与余火仍需让出危险边界和单位轮廓。

它是后续制作和接入目标，**不是当前已完整实现的粒子系统**。当前为 Cocos Graphics 与局部翻页 PNG，通用发射器、完整池化、层级预算、像素合成与强度选项尚需实现；已有局部实现见 [美术风格指南](ART_DIRECTION.md#技能普攻与海克斯特效)。

初始普通近战攻击采用可复用中性斩弧，见[12个关键状态与元素分层](design/BASIC_MELEE_VFX.md)、[v7白色关键帧](../art-source/basic-slash-v7/README.md)，内部光流参考[v4](../art-source/basic-slash-v4/README.md)。武器 / 挥击刃口当前位置最粗、最亮，旧尾迹沿路径逐渐变细、变暗、变透明。当前端按参考呈宽厚斜圆钝轮廓，只有最旧端收尖，不能画成中间鼓、两头尖的月牙；外围默认无散点。当前直接播放[原稿帧序 v3](../art-source/basic-slash-runtime-v3/README.md)，2026-10-22按用户后续反馈采用离线实测的动态曲面，无贴身空洞；原稿刀光、覆盖和F3共用同一测量相位 / 外沿 / 尺度，取消180°裁剪和独立大圆。测量使用原材质的实际混帧，原图不重绘；结束尾迹无伤害。地形 Stencil 限制显示，实际伤害 cue 触发爆点；旧 v1 / v2 停用。该定稿光流使用连续 alpha 与线性过滤，原始 RGB 板在材质中转成白光合成，不冒称透明源图。元素染色仍待扩展，其余像素粒子规则继续适用。

## 攻击与技能特效的判定一致性

**任何攻击、技能相关特效，都要求轮廓清晰，并与实际生效判定范围一致。** 适用于玩家和敌人的普攻、技能、余烬 / 装备触发攻击，以及有空间判定的治疗、控制和护盾；不能只检查敌方预警。

- **先取得判定，再制作美术**：从模拟层读取形状、原点、朝向、半径、角度、宽度、路径与生效相位，使用同一世界投影。动态范围跟随实际状态；不能按PNG包围盒推算伤害，不能为迁就图片偷偷改判定。
- **完整、清晰的生效边界**：外缘、内圈空洞与安全缺口必须符合真实形状，明确哪里会生效、哪里不会。允许内部光流、透明层次和局部亮锋，但不能只画一小段亮锋，却让看不出的整个扇区同时命中；也不能画出看似有效却没有判定的外围光圈。不要求把范围全部填实，可用清楚的整体轮廓或底层范围表达。
- **空间与时间同时一致**：预警显示即将生效的真实区域，并与生效状态区分；生效期间对应当前有效形状；结束后撤掉有效范围的明亮边界。短余迹可保留，但应明显表现为已失效。弹体核心、射线宽度和移动区域按对应时刻的判定对齐，不能只匹配整段动画累计扫过的范围。
- **附属反馈不误导范围**：辉光、拖尾、火花与命中闪光不能扩大、遮糊或伪装出另一圈生效边界。没有独立空间判定的命中 / 受击 / 状态提示，锚定真实事件位置或对应单位，不捏造额外影响范围；不要求每颗反馈火星都有碰撞体。
- **对照实际判定验收**：用F3或等效调试叠层核对中心、朝向、边界、空洞和相位；覆盖主要方向与中间角、移动、不同半径 / 射程、适用的遮挡规则及多效果叠加。验证内外侧目标碰撞体的真实命中结果，不能只看目标贴图中心。

**其他特效不受上述要求限制**：没有攻击 / 技能判定的环境雾、火盆、传送氛围、UI庆祝和装饰光点，不强制清晰硬边或与碰撞范围对应；可以使用柔光、烟雾和自由轮廓，但仍须让战斗信息可读。若环境火焰实际造成灼烧，则属于攻击效果，需遵守上述规则。

这是制作和接入的硬性验收要求，不代表旧效果已全部通过。当前普通近战运行版本已从实际Swing和CollisionWorld生成范围与内部光流；原概念板的环绕角度和半径仍不能直接当作有效范围。

## 丰富表现与信息层次

用短促高亮核心、阶梯拖尾、定向碎片、火星、折线闪电和冲击环组成有力度的爆发。强度来自轮廓变化、方向、节拍和明暗对比，不靠持续铺满屏幕的柔光。角色本体、武器、预警、弹体核心、命中爆发与装饰粒子分别制作，不把可变海克斯效果烘焙进人物帧。

像素化不等于细线化或削弱特效。普通斩击也应有短暂的大块亮面、前厚后尖的形变和有间隙的残影，先把单个主形体做足，再添加粒子。打击感同时依赖蓄力 / 释放的速度差、真实命中爆点、受击动作及音效；局部视觉停姿不暂停权威模拟。具体制作目标见基础近战设计，不用静态图代替动态验收。

**攻击与技能特效要求清晰边缘。** 像素阶梯应有规律地描述连续曲线，不能堆随机锯齿、毛刺和外缘散点。角色使用粗像素，不代表特效也要刻意放大每个折角；先按实际显示尺寸验收轮廓的连续性、锐度和宽窄变化。基础刀光默认无外围粒子，拖尾优先用少量完整条带；元素粒子集中在独立命中层，不能包住整条亮边。不要用模糊滤镜掩盖不干净的形状。

**清晰外缘与丰富内部同时成立。** 刀光内部可有长短不同的光流、交叠薄面、透明通道和局部切光；细节随运动方向和轨迹年龄排列。亮锋是移动的局部最高亮度，越旧的尾迹越暗且alpha越低，不能用不透明深色代替透明。允许内部连续或细分的透明衰减，不强制所有特效只剩3条不透明色带；地面应能透过旧尾迹，外围仍无散点毛边。

基础近战头型沿用用户已基本认可的圈选参考，当前为[v7白色与12状态](../art-source/basic-slash-v7/README.md)：宽厚、斜圆钝、白亮芯集中，带稍错开的发光层；不能再收成针尖或v5的板状平切面。默认效果及辉光按用户要求使用中性白 / 灰，不再用粉紫。当前平滑关键图尚未做像素生产，也不改变世界攻击范围。

视觉优先级：敌人危险边界 / 安全区及攻击方向 → 单位轮廓 → 友方攻击核心 / 必要命中反馈 → 装饰粒子。预警边界、空心环内安全区与逃离方向需要始终读得清；友方效果不能套用敌方预警的完整边线语法。

| 家族 | 像素形态与运动 | 色阶与区别 |
| --- | --- | --- |
| 斩击 / 物理 | 阶梯弧、短直冲击线、沿出手方向的楔形碎片 | 初始普攻用灰白亮芯、石灰中段与深灰暗边；其他金属 / 元素配色独立配置。命中短爆，不画追踪曲线 |
| 火焰 | 方簇火星、上扬锯齿焰舌、短爆开后下落余烬 | 浅奶黄 → 橙 → 砖红，亮芯只占局部 |
| 冰霜 | 菱形 / 三角冰屑、分叉尖晶、短放射断裂 | 冰白 → 冰青 → 深蓝，与火的上扬运动区分 |
| 雷电 | 清楚的阶梯折线、一次分叉、短促节点闪光 | 乳白芯 → 淡紫 / 金黄 → 深靛边，不用全屏频闪 |
| 自然 / 治疗 | 成组叶形像素簇、向内聚合或上升短线 | 浅绿 / 鼠尾草 → 深青；不画与危险圈相同的实边圆 |
| 护盾 / 冲击 | 分段包围轮廓、六边碎片、薄冲击环 | 冷青 / 铜金可选，保留角色内部与地面安全区 |
| 敌方危险 | 明确连续边线、齿记 / 箭头、低亮填充 | 珊瑚赭色配深边；冰地上也需对比，不只靠红绿区分 |

配色从同批共享色板选取。普通单个效果建议 3–5 个色阶；功能亮芯可少量加入象牙色。粒子使用与世界样张相容的源像素密度，建议以 1×1、2×2、2×3 源 texel 簇起步，弧 / 环 / 大碎片可更大；它们不是固定屏幕像素尺寸。主体硬边，衰减可从 100% / 66% / 33% / 0 的离散透明档试起，避免模糊渐变和随机噪点。

## 节奏与制作起点

下列是候选调参范围，需和实际攻击相位、显示倍率及目标设备一起验证，不应写入文档后当作引擎参数已生效。

| 层次 | 建议节奏 | 关键约束 |
| --- | --- | --- |
| 敌方预警 | 从模拟开始准备到实际生效；时长服从技能配置 | 保留完整有效期，不能为追求短促粒子而截短；边界不能呼吸缩放误导范围 |
| 命中核心 | 高亮约 1–2 个视觉姿势，整体约 0.06–0.12 秒 | 与真实出手 / 命中 cue 对齐；不暂停权威模拟，不重复造成伤害 |
| 主爆发 / 斩弧 | 约 0.12–0.25 秒，先快展开后迅速收束 | 保持出手方向和命中核心，低亮装饰可延后散开 |
| 火星 / 碎片 / 短尾 | 约 0.20–0.45 秒 | 数量与亮度衰减，残留不遮住后续预警 |
| 持续状态 | 少量低频簇；例如每 0.5–1 秒一次轻提示 | 状态可合并表达；不让多个装备各自堆常驻大光环 |

像素效果动画可先试 8–12 个视觉姿势 / 秒，爆发关键姿势允许更短。它不是模拟 tick、更不是所有效果的强制帧率；现有播放器只有均匀 FPS，新逐帧时长或特效 cue 需对应实现。禁止靠随机高频闪烁填充帧数。

## 叠加与性能预算

首轮可从普通命中 4–8 个装饰簇、重击 / 精英 8–16 个、Boss 16–24 个试起；全屏装饰簇软目标先试 128 个，同时保留必要的危险信息和实际弹体核心。计数单位是可独立更新的装饰实例，不是贴图内像素或逻辑弹体。此数值只是待压测的起点，不是已测容量；换设备、分辨率或多人数量后重新测定。

后续实现应由效果管理层统一执行合并同源密集命中、局部 / 全局装饰上限、离屏回收、寿命终止与对象池。超预算先去掉旧尾迹、次级碎片、远处低亮簇，再缩短装饰寿命；不得削掉敌方预警、实际弹体核心、仍在生效的攻击 / 技能范围识别层或修改模拟伤害。不同效果重复触发不能无限增加常驻层；池容量与分配峰值需要真实记录，不能凭有池化方案声称性能已通过。

性能先在声明的目标设备、浏览器和分辨率上测基线，再测同场景启用效果后的 CPU / GPU 帧时、P95 帧时、draw calls、活跃 / 峰值装饰数、分配与内存回落。桌面首轮可把稳定 60 FPS、P95 帧时约 16.7ms 作为候选目标；当前没有已公布的最低设备或通过该目标的结果。若未达目标，按上述次序降装饰并记录画面取舍。

## 验收与记录

- 单发检查展开方向、核心、命中时序、阶梯边缘及离散衰减；在浅石、冷霜与深青背景上看清。
- 在 1280×720 和实际 CSS / DPR 组合下平移镜头、移动角色与镜像，检查源 texel 大小稳定、无双线 / 模糊 / 串色。最近邻与像素对齐仍需接入代码验证。
- F2 组合多敌人、多技能、多海克斯；检查玩家脚底、敌人前摇、有效边界、空心安全区与逃离路径。F3 对照真实世界范围，不用装饰尺寸修改碰撞。
- 当前支持 2–4 人合作，涉及联机叠加时按实际人数和网络模式验收；单人密集战斗只能作为单人结果。危险提示不能因同屏玩家增多而消失。
- 暂停、恢复、重开、清关和切图后，装饰按已定义的生命周期冻结或清理，无孤儿节点、残留发射器或持续分配增长。纯表现随机不得消费玩法随机流或改变确定性结果。
- 保存短录像 / 关键帧、效果规格、峰值和性能对比，记录已实现的降级策略及未覆盖设备。静态图不能证明节奏、多人可读性或性能；设计稿也不代表运行验收。

粒子强度、闪光和屏幕震动选项可作为后续需求，当前不能声称已有。高亮核心可以有冲击力，但不使用全屏白闪或高频明暗切换作为常态反馈。
