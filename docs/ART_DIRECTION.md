# 美术风格设计指南

本项目的后续美术统一采用**黑暗、血腥但清晰可读的像素奇幻风**（2026-10-20 用户确定保留像素）。主题是盗火带来盛世、火种熄灭、残星点燃死尸；玩家是渴望火与燃烧的复燃死者。完整故事前提与未定设定见 [世界观](WORLD_LORE.md)。

这份方向替代2026-10-16的“明亮、温和、自然遗迹”基调；像素表现、无固定职业、整身动画一致性、实际战斗可读性继续保留。用户已选择死亡细胞取向，并明确主角**无血迹、无头发、无五官，以阴影面部表达神秘感**。设计图见 [无面复燃主角03](../art-source/rekindled-hero-v3/README.md)，其 [整身生产贴图与动画](../art-source/chibi-runtime-v1/README.md) 已接入。方向已确认，具体细节仍可调整；植物、怪物、装备与地图仍是既有素材，需要分别重制。

同日制作的 [双风格与八方向动作候选](../art-source/rekindled-style-studies-v2/README.md) 保留比较历史：A像素方向被选用，B硬边手绘方向不继续作为主角生产标准。旧A中的头发、五官与血迹同样已废止。03版补充八方向跑步关键姿，并统一其他动作身份；八方向设计板不代表播放器、装备方向和动画已经接入。

2026-10-21用户已确认采用[Q版复燃者](../art-source/rekindled-chibi-v1/README.md)：参考糖豆人的矮胖、圆润比例，保留像素、无血无发无五官与固定整身形象，采用大圆头、短粗四肢和低重心。多人可独立切换衣料配色，共用动画图集，见[主角配色](HERO_COLORS.md)。Q版粗像素完整动作已接入chibi-v1；不要继续按旧修长比例生成新主角。

随后用户要求人物“再像素一些”，减少过于清晰的细节。新制作采用[粗像素修订](../art-source/rekindled-chibi-v2/README.md)的细节密度：明显的大像素簇、少量整块明暗、简化手脚与衣褶，避免头皮斑点、密集布纹和微小破边。保持轮廓清楚，不以模糊画面实现低细节。Q版身份沿用v1，v2仅调整像素语言；设计板不是严格限色的生产图集。

本文用于设计角色、装备、怪物、地图、动作与特效；资源格式、图集切片、挂点和 Cocos 接入步骤见 [美术管线](ART_PIPELINE.md)。新增玩法仍按 [内容扩展指南](CONTENT_ARCHITECTURE.md) 实现。设计建议不代表引擎已经具备对应功能。

实际制作使用 [ember-art skill](../.agents/skills/ember-art/SKILL.md)，其中包含按素材类型选择的 Prompt、动画约束与验收流程。外来动画准则的审核结论见 [审阅结果](ART_ANIMATION_REVIEW.md)。

## 设计依据与优先级

1. 最新要求：世界偏黑暗、血腥，画面不能过暗；采用死亡细胞取向的像素表现。基础人物是死去已久的复燃者，无血迹、无头发、无五官；用阴影面、身体轮廓和关键动作表达，战士 / 法师等构筑由装备属性、被动与技能组合体现，角色形象固定。
2. 运行时已接入 `pixel-v1` 的 26 张生产图集，旧 `living-ruins` 保留兼容。本次四张人物 / 装备图集以稳定 ID 指向 `pixel-v2`，并新增霜图环境、短 VFX、Boss三帧死亡及两阶段出手补片，当前注册36张；这表示 PNG 已接入，不表示严格低分辨率网格、有限色板或二值 alpha 已达标。
3. [原始风格图](../art-source/living-ruins-v1/style-reference.png) 保留为旧版制作参考，不再决定新的整体气氛。构图清楚、地面低噪声等可读性经验可以延续，不能默认新素材仍为温和自然精灵与珊瑚植物。
4. [首批素材提示词](../art-source/living-ruins-v1/prompts.json) 是制作记录。生成图的实际结构与尺寸需要检查，不能将提示词中的左右手、格子尺寸等直接当成事实。

本文的严格像素标准仍是制作目标。当前 ArtLibrary 已配置最近邻，人物姿态和部分屏幕位置取整；混合像素密度、色数和透明边缘仍需精修，实际画面验收以本次构建证据为准。历史 Prompt 和验收报告保留原貌，冲突的风格要求由本文替代。概念稿允许探索新的比例与衣物，但接入前必须重新规划整身全动作画布与锚点，不宣称旧挂点能直接适配新体型。

## 画面语言与细节预算

| 维度 | 设计要求 | 应避免 |
| --- | --- | --- |
| 氛围 | 盛世熄灭后的衰败、死亡、血与燃烧欲望；危险和生命迹象都有明确落点 | 整屏压黑、温和童话感、持续刺眼发光 |
| 形状 | 大像素簇构成体积，阶梯边缘清楚，少量尖角表现武器或水晶 | 细枝、碎叶、密集尖刺和难以辨认的轮廓毛边 |
| 配色 | 每个对象以 3–5 个主要色块组织，点缀色集中在少数位置 | 连续渐变、抗锯齿中间色；每个部位各用一种鲜艳颜色 |
| 明暗 | 每种材质以 2–3 级硬边色阶起步，关键脸部 / 焦痕可试第4级；单位与地面明度分开 | 用均匀灰黑掩盖结构、照片纹理、密集笔触和复杂反射 |
| 线条 | 基准为 1 源 texel 的暖深色阶梯轮廓，内部线少于外轮廓 | 所有石缝和叶脉都用深色描边 |
| 光照 | 沿用同批像素样张的亮面方向与离散色阶；镜像后仍自然 | 强烈单侧投影、烘焙进贴图的地面阴影、局部写实光照 |
| 比例 | 已确认矮胖Q版：大圆头、宽短躯干、短粗四肢与低重心；保留死者身份，手、头和动作在小尺寸下清楚 | 为表达可爱恢复头发或五官、依靠放大查看才能辨认的小配件 |

先做轮廓，再做大色块，最后只增加有辨识作用的细节。每个对象先确定一个主要识别点，例如小精灵的面具、守卫的巨拳、法杖的晶体；其他部位保持安静。删去细节后身份仍然成立，才适合加入战场。

物体细节随屏幕占比增加，不随设定重要程度无限增加。精英怪可以更大、动作更重，但不需要几十块碎石或每片叶子都可见。

## 黑暗、血腥与亮度

- **照明**：战斗地面维持可见的中明度，暗处保留大结构。用冷灰环境、苍白皮肤 / 骨石与局部暖火形成对比；黑色集中在焦化、洞穴、背光面和轮廓，不能覆盖主要通行区域。
- **血腥**：世界、敌人和具体战斗反馈可按对象需要使用血迹、伤口、凝血等大色块。**主角例外：基础身体、裹布、衣物均无血迹，也不画新鲜裂口或红色裸露血肉**；死亡感来自干枯、灰烬和焦化。更重的断肢 / 内脏表现没有在本轮定为全局必备项。
- **血与预警**：地面旧血用低饱和暗红块面，避开完整规则危险圈和高亮边线；新鲜血色及命中飞溅短促。危险边界仍保留最高信息优先级，依靠轮廓和时序区分，不能只靠红色。
- **火**：火有温暖、诱惑和损毁的双重含义。角色身体可有少量余火识别点，表现不要求全身永远燃烧；主动技能的火焰与角色皮肤独立制作。
- **丰富度**：把预算放在轮廓转折、关键材质、身体重心和姿态间的差异。长时间战斗仍要舒适，不把高分辨率设定图的每条碎边都缩进小角色。

建议先比较以下制作色组；具体色号与配比属于美术提案，未固定到运行时：灰骨 `#D0C6AE`、尸灰 `#99958F`、冷灰紫 `#665D70`、烟布 `#777366`、焦黑 `#25232A`、凝血 `#6D252B`、鲜血 `#AE4138`、余火 `#F19739`、火芯 `#FFE2A2`。同屏色板可按身份扩展；不以机械色数代替灰度与战斗尺寸检查。

## 源像素网格与显示目标

以下是**待试样的制作基准**，不是现有运行时开关。源 texel 指设计图中一个逻辑像素；生成器返回更大的 PNG 不代表拥有更多有效细节。

- 在 1280×720 设计坐标下，先比较 1 源 texel 对应 1 或 2 个设计像素的代表样张，记录选定倍率和网格原点；同一世界批次使用一致像素密度。现有约 60 像素高人物及怪物显示尺寸继续作构图参照，不将全部尺寸机械除二，也不先承诺固定低分辨率视口。
- 新单体素材可从 64×64 逻辑画布试起，带长武器或精英可用 96×96 / 128×128，Boss 可用 160×160 或按轮廓扩展；这些是留白起点，身体按实际显示尺度设计。先确定倍率和全动作范围，所有帧保持身体尺度、画布与基准，不强行填满格子。
- 同批建议共享 24–32 个不透明颜色，每种材质 2–3 级色阶；单对象通常取其中 8–16 色。色数是起点，可因身份或危险信息扩展并记录；3–5 个主色块不是 3–5 个总像素颜色。主体边缘使用二值 alpha，效果衰减可用离散透明档。
- 轮廓由有意安排的像素簇与阶梯线组成，避免自动缩小旧图、最近邻放大平滑插画或加像素滤镜冒充重制。保留真实透明孔洞，避免孤立噪点、半透明毛边、无意的双像素边与帧间色板漂移。
- 新像素资源的目标采样为最近邻、无模糊缩放，基准显示采用整数倍率；图集需验证边缘挤出 / 留白及纹理串色。浏览器 CSS 缩放、DPR 和实际视口也要检查，不能只看源 PNG。
- 地面采用45°旋转与统一缩放的等比例战斗平面，不再使用54×28纵深压缩；人物和建筑通过贴图侧面与前后遮挡保留立体感，地面圆 / 环按圆 / 环制作。实际镜头缩放读取 `content/tuning.ts`，参见 [战斗平面](GAME_FEEL.md)，不能把旧 zoom=1 当作当前显示尺寸。当前 ArtLibrary 已配置最近邻，HeroSprite 按整身序列帧播放；这不能保证源 texel 整数显示与全场统一像素密度，Graphics 与 PNG 混合表现仍需检查；禁止对模拟坐标、输入逆投影、碰撞或攻击方向取整来凑画面。
- 玩家全身共用固定比例与地面锚点，切帧只替换完整图像，不旋转分段肢体；腾空与倒地保留原始位移，不逐帧按包围盒缩放。

## 配色与材质

以下表格仅记录**旧版运行时现状**，来源为 [地图配置](../EmberDemo/assets/scripts/ember/content/maps.ts)、[外观配置](../EmberDemo/assets/scripts/ember/content/appearances.ts) 和 [战场绘制](../EmberDemo/assets/scripts/ember/render/ArenaView.ts)。PNG 自带颜色，不会随文档或这些字段自动重绘；新批次按上方黑暗像素方向建立色板，不能原样套用旧版柔和绿 / 珊瑚色。扩色时记录材质或功能用途，不由程序自动量化。

| 用途 | 当前参考色 | 使用方式 |
| --- | --- | --- |
| 庭院浅石地面 | `#EEE5CF`、`#E8DFC9` | 大面积低对比底色，接缝轻于角色轮廓 |
| 自然与边缘过渡 | `#C4C7AD`、`#A1BCAF` | 鼠尾草绿、灰绿；成块分布 |
| 庭院水体 | `#87BFC3`、`#B1D5CE` | 柔和青绿，少量宽水纹 |
| 遗迹暖色点缀 | `#EFCB8B` | 少量金色标志和装饰，避免全场发光 |
| 冰霜地面 / 水体 | `#E6ECE4`、`#8FBECF` | 调冷环境，保持单位与地面的明度差 |
| 火 / 冰 / 雾效果 | `#E4A16C`、`#83CEEE`、`#B59CC6` | 用于元素区分，同时配合形状和运动 |
| 敌人危险预警 | `#D87562` | 优先于环境装饰辨认，不用同等醒目的装饰圈干扰 |

新材质优先表达灰烬、失去温度的石材、染血布料、氧化金属和余火。木材用大面与少量焦裂，石材用几块完整体积，金属用清楚刃口和一块高光，布料用重心明确的大褶皱与少数破口。环境是否保留植物取决于场景设计，不默认铺满明亮绿叶。

不只靠颜色区分机制：远程单位还应有不同的施法姿态或轮廓；危险范围还应有清晰边界和出现时序。转换成灰度后，地面、角色与主要预警仍应能分开。

## 基础人物：固定整身形象

基础人物共同表达“火星点燃的无名死者”。用户确认采用死亡细胞取向像素风，**无血、无发、无五官**：保留光头的人形轮廓，正面是少数深灰硬边色阶组成的无面阴影，不画眼睛（包括发光眼）、鼻、嘴、眉或耳部刻画。不使用兜帽、面具或头盔来代替这个基础头部。灰白干枯尸肤、简朴无血裹布、焦痕与局部小余火是当前提案，胸口余火不表现成流血伤口。身体明暗保持可读，不能因为面部隐藏就把整个人压成黑影。

基础形象不自带盔甲、法袍、兜帽、职业徽记或武器，头、躯干和四肢在每帧内一起绘制，不预留可拼接断面。技能更换不会改变基础身体；身体余火的世界观标志不隐含技能或属性。行走与跑步分别设计：行走重心较直、持续支撑；跑步前倾、屈肘反摆、蹬地和腾空清楚，左右腿交替。关键姿板不等于完整循环，也不自动新增冲刺玩法。

当前运行角色由 [HeroSprite](../EmberDemo/assets/scripts/ember/render/HeroSprite.ts) 显示一个完整身体，不再分头、躯干、四肢，也没有装备叠层。`hero-run / hero-walk / hero-melee / hero-ranged / hero-states` 五张图集各40格；按 S、SE、E、NE、N 五个绘制方向排列，另三个方向整张镜像。每一格的姿势、衣褶与遮挡需整体连贯，不能把新的整身资源再次裁成关节拼装。

跑步20 FPS、行走12 FPS、近战 / 远程 / 施法18 FPS；两帧待机2 FPS，受击一帧，倒地五帧8 FPS。FPS是已绘帧的播放频率，不代表生成了60帧手绘动作。具体切片、固定比例和地面基准见 [生产记录](../art-source/chibi-runtime-v1/README.md)。半透明边缘、色板与步态自然度仍按实际游戏尺寸验收，图片数量不能代替动作质量。

验收身体连续性、八方向、动作首尾和脚底稳定；前后视图不能突然交换，倒地不能重新站起。伤害 / 位移继续由模拟决定，动画只消费信号。

## 装备：构筑数值与物品图标

六个通用栏不限制类型，所有已装备条目都提供属性与被动。装备不改变角色贴图，不生成穿戴层、方向补图或手部握点；weapon/body/head是物品分类。普攻形式仍由余烬决定。

商品图标以主轮廓、材质和一个点缀表达战士 / 法师 / 射手 / 防护等倾向；剑、杖、弓、盾、衣甲和冠饰在商店与详情中保持易辨，物品更强不等于更亮或更复杂。图标与人物动作分开制作。装备购买、替换、卸装后人物应保持同一套图集与比例。

## 怪物：身份与行为一起可读

现有 Demo 敌人仍是木、石、叶、冰和魔法构成的遗迹生灵。它们属于旧美术版本；新世界观中的敌对阵营与外观尚需单独设计，不自动把现有17怪重命名或替换。新肉身敌人可以使用与材质一致的血腥受击 / 死亡，石、金属或冰体不为了统一“血腥”而无故流血。

当前17种怪物已由 MonsterVisual 优先选择对应 PNG 帧组，程序轮廓保留为缺图回退。以下是身份设计要求；具体动作从 EnemyPose 映射到通用帧及专属动作帧，使用实测切片 / 接地锚点，早期 strike 优先于剩余前摇，本体和技能 VFX 分层。

| 类别 | 独立轮廓 | 动作重点 |
|---|---|---|
| 庭院小怪5种 | 水滴单刃、双手三瓣灯、低扁六足甲虫、细柱长枪、三瓣圆花 | 短刺/发射/宽扫/直刺/落点投掷各有准备姿 |
| 霜镜小怪5种 | 三叉叶冠、四足双钳、双扇翼蛾、长鸟铃冠、厚耳四足兽 | 窄针/双拍/三向扇/长瞄准/高频短踢 |
| 精英5种 | 平冠双重拳、U角石羊、圆拱钟身、倒三角双刃、四臂圆轮 | 多次采样、冲锋、双回声、错角斩、空心环 |
| 两Boss | 庭院宽炉四足翻盖、霜镜高拱镜框长臂 | 独立阶段身份、多段出手、长恢复；不是守卫放大 |

当前视角仍是一个三分之四朝向加左右镜像，idle/walk以模拟时间驱动小幅姿态；准备姿/多段strike/阶段变化从EnemyPose读取，不能以动画回调触发伤害。当前死亡约.75秒压低收束，在.9秒内淡出；后续血迹 / 碎裂必须有清理时限且保留地面预警。旧小精灵/守卫 PNG 保留兼容；[17怪Brief](design/MONSTER_ART_BRIEFS.md)保存既有身份和技术约定，其旧自然风格不得覆盖本文的新方向。

体积大的怪物可以扩大视觉轮廓，但受击体积由玩法独立定义。脚底位置、可攻击区域与预警要容易理解，不能让巨大的装饰枝条看起来像必须命中的身体。

## 地图：把细节留给边缘

新战斗区域可使用中明度灰石、覆灰地面、废弃道路与盛世遗存，通行空间连续可辨。残墙、墓碑、熄灭的祭台、焦木、遗骸等属于可选场景语言；雕饰与叙事细节主要在边缘，中心维持低对比接缝和少数血迹，避免每格都密集刻画。

装饰以成组的大形状构图，组与组之间留空。仅少数火盆、余火或暗红标记形成视觉落点，冷灰自然光保留战斗区域的体积。水体和湿地使用宽而少的高光，控制随机闪点与反光；不要用全屏黑雾代替氛围设计。

- 采用等比例地面与固定斜俯视物件的2.5D组合，具体规则见下节；同批物件保持一致视角与光照，不混入正面立绘或近大远小的场景透视。
- 遮挡按脚底深度关系检查；高柱、树冠不应长期遮住主要交战位置、敌人前摇或地面预警。
- 可通行的装饰不要看起来像实心墙；看起来阻挡路线的主体应与实际障碍配置匹配。PNG 本身不产生碰撞。
- 新地图可以改变温度、植被与主标志，但保留安静地面、清楚轮廓和受控点缀的共同规则。

当前霜镜回廊选择新增 `environment-frost-v2` 的九个独立环境部件；庭院沿用原环境图集。地图已扩为两张大图、每图五条起终点/路线和固定敌群；跟随镜头下保持地面安静，路线、敌群、出口必须易读。环境装饰仍主要在边缘，新障碍需配合地图/渲染开发，详见 [整体架构](ARCHITECTURE.md)。

### 环境视角与地面度量

用户已确认后续采用**斜俯视物件贴图 + 等比例战斗地面**的2.5D表现。立体感由物件顶面 / 侧面、材质明暗、独立阴影与前后遮挡提供；移动、射程、弹速、碰撞和交互继续使用同一欧氏世界距离，技术契约见 [战斗平面](GAME_FEEL.md)。这是固定视角的美术表现，不要求改成真实3D场景。

| 素材类型 | 制作要求 | 与玩法的对应 |
| --- | --- | --- |
| 石柱、建筑、宝箱、墓碑 | 用固定三分之四斜俯视画出可见顶面和侧面；保持直立主体比例，不通过压扁整张图制造高度 | 接地位置与底座占地对齐；高处屋檐、枝叶等悬出部分不是额外阻挡 |
| 地砖、道路、地面贴花 | 沿地图方向排列；世界正方形投影为旋转正方形，不画成传统2:1扁菱形；圆形地面纹样保持圆形 | 通行边界、障碍底座和实际空间尺寸一致，不随屏幕位置改变大小或路宽 |
| 树木、墙壁与大型组合物 | 明确地面落点和前后遮挡；主要战斗区域留出可见空间 | 按地面落点排序，不能用树冠 / 屋顶包围盒决定碰撞或排序；跨通道大物件必要时拆分遮挡段 |
| 阴影与地面效果 | 阴影独立、低对比，允许风格化椭圆；危险圈按实际范围制作 | 阴影只表达落地与高度；规则圆 / 环保持圆形，扇形保持角度，不能随物件绘画透视压缩 |

地面45°指世界网格在画面中的旋转，不是强制所有物件使用45°俯角。同批物件的具体顶面可见比例由代表样张确定并沿用；斜俯视画法不引入近大远小、远端道路收窄或上下方向速度修正。人物与直立物保持自身比例，不对整个场景或父节点施加非等比缩放。

制作 brief 需记录素材属于地面还是直立物、目标世界占地、游戏内尺寸、地面锚点（原点与单位）、朝向、遮挡关系及阴影是否独立；说明源图是否已按屏幕方向绘制，避免导入时重复旋转 / 压缩。只在制作说明或独立示意层标注，不将锚点、碰撞线、文字和阴影烘焙进主体PNG。PNG不自动生成碰撞、拆层或遮挡淡化功能，需要新能力时另做渲染接入。

验收时把一个代表物件放在实际地面网格上，绕行前后和左右、核对F3底座与阻挡，检查人物脚底及危险圈的可见性，再检查镜头移动和画面不同位置下的尺度。源像素与低噪声规则继续适用；整套环境重制仍为ART-09，本文确认原则不表示旧环境素材已完成适配。

## 技能、普攻与海克斯特效

视觉优先级为：敌人危险边界 / 安全区和主要攻击信息 → 人物 / 敌人轮廓 → 友方攻击核心与命中反馈 → 装饰粒子 / 环境。像素粒子的形态、节奏、叠加与性能制作基准统一见 [像素特效规范](PIXEL_VFX.md)。多种海克斯同时触发时，仍要看清人物脚下、敌人前摇和逃离方向。

- 普攻沿鼠标方向挥击或发射。刀光、箭和法球应指向实际出手方向，不能画成锁定敌人的追踪效果。
- 所有攻击 / 技能特效都必须轮廓清晰，与模拟层实际范围、朝向及生效时段一致，覆盖双方普攻、弹体、范围技能与触发效果，不能只校验预警。统一投影真实判定形状，空洞 / 安全缺口也要对应；细则见[判定一致性](PIXEL_VFX.md#攻击与技能特效的判定一致性)。
- 等比例地面使世界圆显示为圆、扇形角度保持不变；不要从美术像素反推伤害。身体阴影或没有独立空间判定的护盾外壳可按体积绘制，但不能冒充额外有效范围。有实际拦截范围的护盾仍需对齐判定。环境 / UI / 纯装饰特效不受清晰硬边与判定对齐要求限制，可有柔光、烟雾和自由轮廓，同时让出战斗信息。
- 弹体主体清楚，拖尾和命中闪光短而克制；不要用遮住碰撞核心的大光晕暗示更宽命中范围。
- 火焰靠暖色和上扬形态，冰靠冷色和简洁尖角，护盾靠包围轮廓等不同形状表达。颜色只是其中一种信息。
- 持续状态使用少量、低频反馈；爆发特效快速出现和收束，避免长时间铺满地面的高亮残留。
- 新装备和海克斯默认不叠加常驻光环；确有状态提示需要时，设计合并或减弱表现，保留危险预警。

现有表现混合 Cocos Graphics 与 `PixelVfxView`：新增火 / 冰 / 挥击 / 护盾共16帧短翻页，使用快照 cue 年龄、最多24个复用节点，并避让敌方危险边界。主要敌人预警、弹体核心与数字仍独立绘制；这不是完整粒子发射器或统一像素合成，密集场景可读性仍需实际验收。具体伤害始终由模拟层与碰撞系统结算。

普通近战已改为[原稿帧序环扫](../art-source/basic-slash-runtime-v3/README.md)：直接采样用户确认的白色12格，按实际 Swing 相位插值；当前亮锋最厚最亮，旧尾迹渐暗变透。判定随亮锋世界轮廓扫过，空洞 / 旧尾迹不伤害；不使用旧4帧技能翻页或完整扇区底板。角色身体仍为既有整身序列帧，本轮没有增加身体手绘帧数。

## 动作设计与整身稳定性

动作应有明确的准备、出手、恢复。待机幅度小，移动有稳定脚底基准，受击是短反馈，死亡结束后不继续走动。保持帧间体积、服装和握持关系一致，避免生成图常见的肢体增减、头大小跳变或武器换手。

新主角动作强调僵冷身体被火驱动：待机内收、奔跑反摆、攻击蓄力与回收。丰富度来自完整身体的肩胯转动、重心变化及布料跟随；不能用整图旋转或缩放代替完整动作。

怪物当前使用 MonsterVisual 的 PNG 相位姿态与左右镜像；人物使用 HeroSprite 整身帧组。两者按模拟时间采样、暂停冻结，动画不决定伤害；没有使用 Spine、分段玩家骨架或装备换皮。

动画表现服从实际攻击时序。现有行为的前摇不足以容纳新动作时，应一起调整表现或经玩法开发修改参数；不能靠动画播放完毕回调扣血。缩慢播放有助于检查关节，但最后必须回到正常速度检查战斗可读性。

## 给其他 AI / 美术的任务模板

将下列字段填清后制作素材；优先附同类运行时 PNG 作为身份、比例与挂点参照；像素风格以本文和新候选为准。概念预览可以含背景，交付图集必须单独说明透明与切片要求，不能直接把概念海报作为运行时资源。

```text
任务：为 Project Ember 制作 [对象名] 的 [概念预览 / 运行时整身图集 / 物品图标]。
先读 docs/ART_DIRECTION.md 和 docs/ART_PIPELINE.md。
参考资源：[指定候选 / 当前同类 PNG 路径]；运行时修复保留身份、比例、挂点和视角，重设计概念则说明可探索的范围。
世界风格：盗火盛世熄灭后的黑暗像素奇幻；血、灰烬与局部余火，画面保持清晰。
故事依据：docs/WORLD_LORE.md；共同主角身份为复燃死者，具体造型采用明确指定的候选。
像素语言：清楚像素簇、3–5 个主色块、以2–3级硬边色阶起步，关键材质有目的地加层次。
像素规格：[逻辑画布、共享色板、网格原点、源 texel 显示倍率]。
轮廓：阶梯边、基准 1 源 texel 描边，无抗锯齿、模糊或假像素滤镜。
对象身份 / 主要识别点：[填写一个主要识别点及战斗作用]。
基础人物保持固定中性形象；装备只提供属性、被动与物品图标，不生成穿戴层。
视角与尺寸：[填写当前视角、游戏内显示尺度、图集目标尺寸]。
环境资源：斜俯视物件 + 等比例地面；填写地面 / 直立分类、世界占地、
地面锚点、遮挡关系、阴影分层及源图是否已按屏幕方向绘制。
布局：[列数、行数、每格内容、留白、脚底基准；整身需列出共同地面锚点]。
动作：[逐项写准备 / 出手 / 恢复等姿态，保持体积、朝向和装备一致]。
运行时资源：真实透明 alpha，干净轮廓，不含文字、水印、网格线、
棋盘背景、地面投影、背景光晕或额外人体；头饰开脸区域透明。
细节限制：无密集雕花、碎叶、叶脉、划痕、写实纹理和大范围强光。
交付：[PNG、实际尺寸与帧序、挂点说明、参考与生成记录、验证画面]。
验收：实际战斗尺寸、浅 / 深背景、左右镜像、混搭、动作和密集战斗。
```

生成尺寸、透明度、帧序和部件数量都需实测。若输出不符合网格或动作一致性要求，修正素材或明确修改切片方案后再接入，不靠每帧随意缩放和偏移掩盖问题。

## 交付验收

按本次改动选择相关项。静态预览通过以后，还需在实际游戏中检查；设计文档修改本身不需要重建游戏。

- **缩小检查**：在正常 1280×720 设计尺度下查看，能辨认主体、装备和攻击方向；再放大检查接缝。不要只提交放大立绘。
- **像素检查**：记录逻辑画布、色板、网格原点与实际显示倍率；最近邻 / 整数显示、镜头移动、连续姿态及 CSS / DPR 下无模糊、爬边、像素粗细交替。尚未适配的运行时项单独列出。
- **低噪声检查**：地面和装饰没有抢过角色 / 预警；灰度查看仍能分层；连续移动时没有密集闪烁细节。
- **透明检查**：在浅石色和深色背景上检查，边缘无棕色光晕、白边、矩形底色和假透明棋盘。
- **装备独立检查**：购买、替换和卸装后角色图集、比例和朝向规则不变；六栏属性与被动继续生效，物品图标可独立识别。
- **怪物检查**：单体和一群敌人都能辨认；攻击前摇、出手、受击、死亡完整，帧间大小稳定。
- **环境检查**：按[环境视角与地面度量](#环境视角与地面度量)核对等比例占地、地面锚点、前后遮挡与独立阴影；地图平移不改变物件大小，地面纹样及危险范围不被物件透视压扁。
- **判定检查**：用 F3 对照预警、弹体、障碍与命中体积；不用改碰撞参数掩盖纯美术锚点问题。
- **压力画面**：用 [F2 开发者模式](DEVELOPER_MODE.md) 组合多种技能和海克斯、刷新多只敌人；确认关键预警和地面仍可见，再用普通战斗流程验收。
- **工程检查**：按美术管线导入资源、生成元数据、构建并执行相关回归；提交素材来源、配置和验证说明，不提交生成的构建目录。

完成后记录当前已实现内容与仍需开发的能力。若只能提供风格预览，应明确标为预览，不能当成已可换装、可动画或可参与碰撞的成品资源。
