# 全单位统一属性系统 · 设计基线 v1

日期：2026-10-16。对应任务：STAT-01 / STAT-02；实际API、来源运算、迁移数值与验证见 [统一属性实施记录](ATTRIBUTE_IMPLEMENTATION.md)。

**统一属性模型已由 STAT-02 接入运行源码。** 本文保留产品规则与验收契约，具体API与版本化项目边界以 [实施记录](ATTRIBUTE_IMPLEMENTATION.md) 为准，模块职责同时参见 [整体架构](ARCHITECTURE.md)。用户已核对属性体系的解释，并确定以下两项简化；其余采用英雄联盟端游的通用属性机制。

## 1. 已确定的产品规则

1. **技能加成只使用总攻击力。** 玩家面板、技能描述和伤害表达式只有「攻击力 / AD」；不提供基础 AD、额外 AD 两种技能系数。装备触发伤害、增益附伤也遵守这一约定，避免换个入口重新引入相同复杂度。
2. **只保留全能吸血 `omnivamp`。** 不增加生命偷取、物理吸血、法术吸血等并行属性；装备与增益统一显示「全能吸血」。全能指覆盖伤害类型，不代表移除伤害类别、目标类型和治疗限制。
3. **所有战斗单位使用同一套属性与结算。** 玩家、普通敌人、精英、Boss、未来召唤物和可攻击单位共用模型；差别来自模板、能力、属性来源和明确的特殊效果。弹体、普通地形装饰不是战斗单位。
4. 保持无固定职业、技能奖励自由组合、装备确定性购买与换装外观。属性不改变鼠标方向攻击、CollisionWorld 判定或固定步进。
5. 参考端游通用规则，不混用手游、云顶之弈、竞技场的模式数值，也不把某个英雄的特殊被动当成全局规则。参考版本和本项目规则版本固定记录，不能联网读取最新规则后自动改变游戏。

内部仍记录「单位模板 / 等级来源 / 装备 / 增益 / 状态」以正确叠加与撤销；**记录来源不等于允许技能读取基础 AD / 额外 AD**。额外生命等其他明确的属性概念未被此次简化删除。

## 2. 属性、运行状态与能力分开

| 数据类别 | 示例 | 归属 |
| --- | --- | --- |
| 模板参数 | 初始生命、AD、基础攻速、攻速收益系数、成长配置 | 共享只读定义 |
| 属性修正 | 装备 +20 AD、状态减甲、增益 +20 急速 | 每单位独立的来源列表 |
| 最终属性 | 最大生命、总 AD、AP、护甲、实际攻速 | 统一解析器产生的只读结果 |
| 运行状态 | 当前生命 / 法力、护盾实例、剩余冷却、控制计时 | 模拟 / 战斗系统 |
| 能力与分类 | 能否移动 / 普攻、资源类型、控制免疫、单位类型、所属阵营 | 单位模板与明确状态规则 |
| 内容行为 | 技能系数、伤害类型、命中形状、普攻弹体 | 技能 / 攻击 / 效果定义 |

怪物也可拥有 AP、暴击、全能吸血、急速；不用的属性为 0。不能因为 `team === 'enemy'` 就跳过属性解析或增益规则。静止单位通过能力禁用移动，而非用异常数值与移速保底公式对抗。

没有法力机制的单位声明 `resourceKind: none`；有法力机制的单位使用同一套最大法力、回复、消耗检查。属性系统支持等级成长，但经验获取、升级节奏、现有技能是否新增蓝耗属于内容设计，不由这次基础设施改动凭空决定。

## 3. 属性字典

下列字段已进入统一 Attributes 类型；moveSpeed 的raw来源值、面板阈值后点数与世界格速度的区别见实施记录。百分比内部统一用小数（25% = 0.25）；急速是点数（20 急速 = 20）；时间用秒。AD / AP 是点数，不是百分比威力。

| 分类 | 字段 / 中文名 | 单位或语义 |
| --- | --- | --- |
| 生存 | `maxHealth` 最大生命 | 点 |
| 生存 | `healthRegen` 生命回复 | 点 / 秒；UI 可换算每 5 秒 |
| 资源 | `maxMana` 最大法力 | 点 |
| 资源 | `manaRegen` 法力回复 | 点 / 秒 |
| 输出 | `attackDamage` 攻击力 | 最终总 AD，唯一 AD 加成入口 |
| 输出 | `abilityPower` 法术强度 | AP 点数 |
| 普攻 | `attackSpeed` 攻击速度 | 次 / 秒，间隔由其派生 |
| 普攻 | `attackRange` 攻击距离 | 逻辑世界距离；独立于贴图大小 |
| 暴击 | `critChance` 暴击几率 | 0–1；超过 100% 不默认转化收益 |
| 暴击 | `critDamage` 暴击伤害倍率 | 2 表示造成 200% 伤害 |
| 防御 | `armor` 护甲 | 可因削减变负 |
| 防御 | `magicResist` 魔法抗性 | 可因削减变负 |
| 穿透 | `armorPenFlat` 固定护甲穿透 / 穿甲 | 护甲点数 |
| 穿透 | `armorPenPercent` 百分比护甲穿透 | 0–1 |
| 穿透 | `magicPenFlat` 固定法术穿透 | 魔抗点数 |
| 穿透 | `magicPenPercent` 百分比法术穿透 | 0–1 |
| 技能 | `abilityHaste` 技能急速 | 点数 |
| 机动 | `moveSpeed` 移动速度 | 属性面板速度点；经比例映射到格 / 秒 |
| 续航 | `omnivamp` 全能吸血 | 百分比；来源相加，不拆伤害类型 |
| 辅助 | `healShieldPower` 治疗与护盾强度 | 对适用治疗 / 护盾的加成 |
| 抵抗 | `tenacity` 韧性 | 适用控制的时长减免 |
| 抵抗 | `slowResist` 减速抗性 | 减速幅度减免 |

基础攻速、攻速收益系数、成长曲线属于模板参数；吸血效率、治疗削减、伤害增减、抗性削减属于带适用条件的效果规则，不混成一组无条件乘数。特殊技能急速可按技能标签扩展；QWER 是槽位，不能把 R 自动当成固定终极技能。

金币、经验、背包、技能等级、体积和视野不塞入这份数值表。它们可与属性互动，但具有独立的生命周期与行为。

## 4. 来源与叠加

统一入口为：**模板及成长 → 装备 / 永久增益 → 临时状态 / 光环 → 各属性专用合成 → 合法区间与最终属性**。按来源重算，不在穿脱装备时反复加减已经派生的结果。

每个修正至少记录 `sourceId / instanceId / stat / operation / value / stackingGroup`；临时修正由状态系统管理到期。重算按稳定顺序执行，相同构筑不因装备穿戴先后改变结果。

| 类型 | 合成约定 |
| --- | --- |
| 普通固定属性 | 同类固定加成求和；再按该属性定义处理百分比修正 |
| AD | 内部汇总模板、成长及所有加减，表达式最终只获得 `attackDamage` |
| AP | 固定 AP 求和；百分比 AP 增幅按相应效果叠加规则计算 |
| 攻速 | 额外攻速加成进入收益系数，不用统一的「最终属性乘百分比」替代 |
| 急速 | 同类急速点数相加；从最终急速派生冷却倍率 |
| 暴击率 / 全能吸血 | 同类加成相加；暴击概率截断至 0–1，全能吸血不擅自增加 100% 上限 |
| 独立百分比穿透 / 抗性削减 | 乘算剩余比例；同一个具名效果是否叠层由该效果定义 |
| 韧性 | 按来源组处理；独立乘算组使用剩余时长乘积，不能把所有来源无条件直接相加 |
| 多个普通减速 | 强者生效；各实例保留自己的时长，最强减速结束后较弱减速可继续生效 |
| 具名唯一被动 | 按 stackingGroup 去重、取强或叠层，不因来自两件装备就默认叠加 |

百分比作用于「模板值 / 额外值 / 总值」必须在对应属性规则中明确；不能用一个通用的 `(基础 + 固定) × 所有百分比` 公式冒充全部 LoL 属性。新增特殊覆盖需要定义与测试，不在 GameWorld 按装备 ID 特判。

## 5. 技能表达式与伤害身份

技能、普攻附伤、治疗和护盾可共享数值表达式。示例仅演示格式，不是新技能最终数值：

```text
斩击：50 + 1.2 × 攻击力，物理伤害
火弹：40 + 0.6 × 法术强度，魔法伤害
混合加成：30 + 0.5 × 攻击力 + 0.4 × 法术强度，魔法伤害
生命附伤：0.03 × 施法者最大生命，物理伤害
```

表达式的 AD 引用只能是 `attackDamage`，校验应拒绝 `baseAttackDamage / bonusAttackDamage`。条件、描述、预览和效果处理器使用相同表达式，不能在 UI 写总 AD、运行时偷偷读额外 AD。最大生命 / 已损生命 / 目标生命比例等要明确读哪个单位、哪个时点，以及对特定单位是否有上限。

每笔伤害分别记录：

- `damageType`：physical / magic / true，决定防御结算。
- `delivery`：attack / spell / periodic / proc / pet 等来源行为；范围形状另外记录，不能只靠单个互斥标签表达全部性质。
- `sourceId`：实际伤害单位；可另有 `ownerId` 记录召唤物归属，归属不自动转移装备、吸血或击杀触发。
- 暴击资格、攻击特效资格、吸血资格、技能 ID、原始事件及 `rootId / depth / proc`。

火焰 / 冰霜是内容标签，不自动决定魔法伤害。敌人不是伤害类型；敌人普攻和敌人技能仍应区分。采样时点由行为契约明确（出手 / 发射 / 命中 / 持续跳伤），不可一部分系数出手采样、一部分无意在命中后重复放大。

## 6. 核心计算规则

### 6.1 护甲、魔抗与穿透

同一套函数分别用于物理护甲和魔法抗性；真实伤害绕过这一步。

```text
目标有效抗性：固定削减 → 百分比削减 → 攻击者百分比穿透 → 攻击者固定穿透

若抗性 R ≥ 0：伤害倍率 = 100 / (100 + R)
若抗性 R < 0：伤害倍率 = 2 - 100 / (100 - R)
```

固定削减可以造成负抗性。百分比削减不作用于已经不大于 0 的抗性；穿透不能把抗性压到负数，也不改变已有负抗性。削减修改目标供所有攻击者使用的抗性；穿透仅影响本次攻击者的结算。[计算顺序参考](https://leagueoflegends.fandom.com/wiki/Armor_penetration)

例如 100 护甲，先固定削减 10，再百分比削减 20%，随后穿透 30% 和固定穿透 10，最终为 `(100 - 10) × 0.8 × 0.7 - 10 = 40.4`。200 点物理伤害在没有其他修正时造成约 142.45 点减伤后伤害。

伤害增减、免疫、格挡等还有各自适用范围；真实伤害不受普通双抗和普通减伤处理，但仍可能被护盾吸收，也不能无条件越过无敌。特殊效果是否能改变真实伤害须显式声明，不能误用一个覆盖所有伤害的通用倍率。

### 6.2 攻速与急速

常规攻速先算 `基础攻速 + 攻速收益系数 × 额外攻速比例`，再处理适用的攻速降低、特殊倍率和上限；普通攻击间隔由 `1 / 最终攻速` 派生。普通基准上限按官方公开规则取面板 3.0 次 / 秒，突破上限须由能力明确声明。[官方攻速调整](https://www.leagueoflegends.com/en-us/news/game-updates/patch-2025-s1-3-notes/)

```text
冷却倍率 = 100 / (100 + 技能急速)
技能冷却 = 基础冷却 × 冷却倍率
```

50 急速使 10 秒冷却变为约 6.67 秒，100 急速变为 5 秒；不把急速写成冷却缩减百分比，不沿用旧项目 `haste: 0.15` 的单位。[官方急速设计](https://www.leagueoflegends.com/en-au/news/riot-games/preseason-2021-champion-class-item-goals/)

攻击前摇、技能施法时间、弹速与技能冷却是不同概念，不因急速提高就一起缩短。直接减少剩余冷却的效果另走冷却操作；不把扣减秒数再次乘急速。正在冷却期间的属性变化按冷却实例契约处理，不在每帧重置剩余冷却。敌人 AI 也必须消费同一攻速 / 冷却数据，而非继续读取独立固定间隔。

### 6.3 暴击

普通暴击倍率的参考基准为 2.0；Riot 26.1 已将一般英雄基础暴击伤害调回 200%。当前 Demo 的 150% 属于旧实现，迁移时需同时更新珠光护手等文案与测试，不能保留隐藏硬编码。[官方暴击基准](https://www.leagueoflegends.com/en-us/news/game-updates/patch-26-1-notes/)

普通普攻可暴击；技能通常不自动暴击，由技能或增益解锁。技能可使用暴击额外部分的指定比例：`1 + 比例 × (critDamage - 1)`。普攻里的附伤不会默认跟随本体重复暴击；是否共享一次暴击结果由攻击定义明确。暴击随机继续使用可恢复的有种子随机流，不使用全局 Math.random。

### 6.4 移速、韧性与减速抗性

移速使用固定加成、百分比加成、效果专属倍率、减速及软阈值规则；不直接把装备上的 10% 当成 +0.1 格 / 秒。LoL 速度点与当前地图格之间用统一比例转换，阈值也按同一比例，不能把 415 这样的数直接当世界格速度。

韧性缩短适用控制的时间，减速抗性降低减速幅度；二者不能合并。2 秒的可缩短控制在 30% 韧性下为 1.4 秒（未触及最短时长边界）；50% 减速在 20% 减速抗性下为 40%。击飞 / 强制位移、压制等不能被普通韧性统一缩短；免疫与不可行动能力另行判断。

移速软阈值、韧性来源组和最短时长等边界需收敛为版本化规则表，实施时补齐逐项对照测试，不凭旧版本记忆或一条全局 clamp 代替。没有相关新机制的内容不得挂一个尚未消费的字段伪装为完成。

## 7. 唯一吸血属性与治疗

`omnivamp` 对符合条件的物理、魔法、真实伤害均适用。普攻和技能不会走两套吸血属性；击杀治疗、技能直接治疗、生命回复仍是不同治疗来源，不能把它们都改名为吸血。

```text
请求吸血量 = 可计入吸血的减伤后伤害 × 全能吸血比例 × 该伤害的吸血效率
有效治疗量 = 应用适用治疗修正后，截断至目标缺失生命
```

必须保留 `postMitigation / shieldAbsorbed / healthLost / overkill / effectiveHeal` 等不同结果，不能把伤害事件的一个 `amount` 同时当成所有数值。护盾吸收和过量伤害下的吸血基数需要按参照规则单独覆盖；不要无意使用 `healthLost`，导致护盾把吸血一并禁用，也不要对未成立、免疫或已死亡目标的伤害发放吸血。

Riot 26.1 的全能吸血说明恢复通常 100% 效率，并列出宠物、持续伤害及对小兵范围伤害的 33% 效率规则。**保留按伤害类别与目标类型查询效率的能力，不把所有 AOE 永久减成 1/3，也不沿用 14.1 对小兵 / 野怪统一 20% 的旧规则。** [官方吸血调整](https://www.leagueoflegends.com/en-us/news/game-updates/patch-26-1-notes/)

玩家、小兵、野怪、召唤物与建筑的规则分类独立于阵营和精英等级。现有 PvE 敌人不能仅因贴图小就当作 LoL 小兵；分类和对应吸血效率需要在内容迁移表中明确。资料对具体目标范围有歧义时，标记待核验条目，不以额外简化冒充用户已确认的规则。

普通治疗 / 护盾强度作用于符合条件的治疗和护盾；不把它自动套在自然回复或全能吸血上。受到治疗增幅、重伤、禁止治疗等是另外的适用规则。输出强度和承受修正不能重复应用；普通重伤取适用的最强效果，不因多个来源无限相乘。

吸血产生的治疗继续进入 CombatEngine，保留来源和根事件信息；有效治疗才触发相应治疗事件。治疗转伤害、附伤再吸血等链条保留深度、预算与去重约束，不能因引入吸血绕过现有保护。召唤物自身回血与治疗主人必须在定义中区分，不凭 ownerId 自动执行两次。

## 8. 运行状态与结算入口

最大生命 / 法力改变时不能凭属性重算生成战斗治疗。当前换装规则保持「不免费回血，超过新上限时截断」；需要补充生命的成长或变身效果必须显式提交资源变更。死亡单位不因上限增加或自然回复自动复活。

护盾保留施加者、受益者、剩余量、可吸收类型、剩余时间与叠加规则；不同来源独立过期，不能继续仅用一个全局 shieldTime 覆盖全部护盾。施加护盾和治疗统一走战斗入口，表现层只读取结果。

每次伤害的流程为：确认命中与资格 → 读取表达式及采样属性 → 处理合法暴击 / 伤害修正 → 计算有效抗性 → 得到减伤后伤害 → 护盾与生命结算 → 生成伤害 / 击杀结果 → 按资格处理吸血及事件链。免疫和特殊覆盖插入明确阶段；伤害类型与事件来源始终保留。

自然回复、状态、冷却与修正过期沿固定步进推进；暂停和非战斗冻结规则沿用项目阶段契约。波间补给仍是阶段恢复，不伪造为吸血或技能治疗。

## 9. 架构落点与旧内容迁移

STAT-02 已按下列职责接入纯逻辑模块，只保留一份核心规则：

| 模块 / 入口 | 职责 |
| --- | --- |
| `combat-core/attributes/` | 属性定义、来源合成、只读结果、规则表、解释明细；不依赖 cc / DOM |
| `content/` 单位模板 | 玩家与敌人基础属性、能力及分类 |
| `simulation/EquipmentSystem.ts` | 装备事务及修正来源，不再拥有另一套只供英雄使用的计算公式 |
| `simulation/SkillSystem.ts` / `EffectHandlers.ts` | 消费统一表达式、请求伤害 / 治疗 / 护盾 |
| `CombatEngine` | 按 sourceId / targetId 获取属性，统一暴击、双抗、吸血和事件结果 |
| `EnemyBehaviors.ts` | 按单位最终属性移动与攻击；保留 AI 决策职责 |
| `GameWorld` | 单位实例、更新顺序、属性脏标记、生命周期与资源边界 |
| `RunCheckpoint` / 房间协议 | 保存可重建来源、持久状态及版本，显示快照与恢复点分开 |
| HUD / 商店 / F2 | 相同字段、相同单位、相同描述，提供属性来源明细与验证配置 |

迁移时必须处理：

1. `HeroStats / StatBonus / deriveStats` 迁移到全单位模型；兼容接口如短暂存在只能转调，不复制公式。
2. `EnemyDefinition.hp / damage / speed / interval` 转成模板和行为引用；旧 AI 的 `windup + interval` 实际节奏需测量，不能只取 interval 倒数便宣称手感完全一致。
3. 旧 `skillPower` 是百分比全技能放大，**不能直接改名成 AP**。逐项给现有技能配置 AD / AP / 生命等系数，再确定装备点数；技能类型和魔法抗性也逐项迁移。
4. 旧 `haste: 0.15` 转为 15 急速；旧百分比移速、攻速按各自规则映射，记录基准攻速和收益系数。
5. 移除 CombatEngine 中只允许 hero 暴击 / 使用规则的隐式限制。敌人拥有增益与属性，不等于拥有玩家商店、奖励 UI 或背包。
6. 原来只对玩家生效、抵挡一切非真实伤害的 armor 政策拆为所有单位的护甲与魔抗；不偷偷用同一数值同时填两种抗性来掩盖平衡变化。
7. 原 `trueDamage` 布尔与 `unscaled` 迁移为明确类型 / 表达式处理；一次伤害包含多种类型时分组件结算，避免真实附伤再次经过抗性。
8. 保存来源 ID、永久层数、资源及必要状态，再重算派生属性；不从客户端提交的最终 AD / 护甲覆盖权威状态。协议与存档版本升级，旧版明确迁移或拒绝，不能静默换规则。

新技能与装备数值应在对应内容任务中设计；本文件的公式示例不自动成为首批平衡数值。完整 LoL 特殊英雄机制、升级玩法和技能资源经济不因接入属性系统自动加入。

## 10. 验收与实施边界

| 验收项 | 必须能复核的结果 |
| --- | --- |
| AD 简化 | 初始 60 AD + 装备 40 AD，`50 + 1.2 AD` 得到 170；不提供基础 / 额外 AD 表达式 |
| 类型分离 | 同一个 AD 加成表达式可造成魔法伤害，并由魔抗结算 |
| 抗性 | 200 物理伤害对 100 护甲为 100；对 -50 护甲约为 266.67；穿透不能制造负抗性 |
| 穿透顺序 | 第 6.1 节例得到 40.4 有效抗性与约 142.45 伤害 |
| 急速 | 10 秒基础冷却在 0 / 50 / 100 急速时为 10 / 6.67 / 5 秒 |
| 全能吸血 | 满效率、无治疗修正时，100 减伤后伤害与 10% 全能吸血请求 10 治疗；缺 6 生命只实际治疗 6 |
| 吸血边界 | 物理 / 魔法 / 真实、护盾、过量伤害、免疫、DOT / AOE / pet、不同目标分类分别测试 |
| 统一单位 | 相同属性与行为的玩家 / 敌人得到相同数值结果，阵营仅改变敌我与选择规则 |
| 修正撤销 | 重复换装、状态过期、光环离开后无累计漂移；不同获取顺序不改变结果 |
| 动态状态 | 多护盾独立过期、减速取强与回退、控制免疫和回复 / 死亡正确 |
| 恢复 / 联机 | 第二玩家和召唤物不串属性；恢复来源后结果一致，不重复叠加永久增益 |

STAT-02 先建立规则表和纯函数测试，再迁移玩家 / 敌人、伤害与治疗，最后接入 UI / 开发模式 / 恢复协议。LoL 未完全公开或资料冲突的边界必须记录核验依据，不能声称已做到逐帧复刻。

实现交付需运行 `pnpm check`、真实 Creator 构建，以及普通商店 / 奖励、战斗判定和多人恢复的对应回归。STAT-02 已运行 pnpm check（15个文件170项测试通过）；真实Creator构建和浏览器验收以本次任务的最终交付记录为准。迁移改变技能系数、暴击倍率、护甲/魔抗语义及移速加成收益，具体数字与规则边界见实施记录。
