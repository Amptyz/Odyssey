# 普通近战：原稿实测曲线与同源命中

2026-10-22用户反馈半圆判定大于刀光、180°裁剪截断特效。当前以**实际材质显示的外沿**为基准，离线测量并生成动态曲面；不再使用固定圆 / 半圆或外圈亮锋方块。曲面填到人物脚底，保留贴身命中。

## 量化方法与结果

`pnpm measure:melee`（或`node --import tsx scripts/measure-melee.mjs`）只读原PNG，通过浏览器解码RGB，复现`melee-keyframes.effect`的亮锋位置配准、双帧混合和去黑底alpha。可见边界定义为合成alpha≥0.1；角度每0.5°采样，材质时间每0.375ms采样，共321个样本。轮廓预留0.75源像素的像素覆盖余量。

结果生成到 `content/melee-outline.ts`，包含原图SHA-256和81个实际播放相位的径向外沿；详细数值在[测量报告](../../reports/melee-outline-measurement.json)。战斗运行时不读图像、不依赖DOM或动画回调。

这些是逐帧变化的弯曲外沿，不能用单一角度和圆半径代替。材质混帧也会改变轮廓，不能只测原图单格包围盒。原282像素高窗口还裁掉第6/7格上沿光流；现向上扩11像素，窗口356×293，原点(178,149)，行起点79 / 412 / 745，保留同一个人物锚点并避开标题。

6个关键状态的曲线外沿到可见像素的欧氏距离均值约1.1源像素；95%约在1.6～1.8源像素内，最大约3.11源像素。基础镜头每源像素约1.32屏幕像素，详见报告。填到脚底的内部区域为明确保留的贴身命中区域，不能将其当作外沿拟合误差。

## 空间与动画共同定义

- `MeleeSweep.meleeArea`按测量数据生成**一个连续曲面多边形**。从原点连接到自然弯曲外沿，没有旧亮锋内圈盲区。
- `meleePoseIndex`统一选择图片与碰撞的同一个测量相位。普通有效期共80段，每段1.5ms；禁止图片连续推进、碰撞却取另一帧，也不能用未来轮廓扩大当前显示范围。
- `MELEE_OUTLINE.referenceRadius`来自实测全部播放相位的最大外沿，默认`attackRange=5`统一缩放轮廓和图片。各方向、各相位的实际边界仍由曲线决定；5不是整个圆都有效。
- `meleeRotation`共同旋转图片和世界轮廓，标准模板缺口对准攻击方向的背面。偏角由原稿后段覆盖角测算，约等价于81.25°；不再保留独立的手调35°图片偏角。
- 显示Stencil和F3读取同一块曲面。有效期有淡白内部覆盖，取消独立大圆外沿，不用180°直径裁剪原图。
- 最淡的外围光流按明确alpha门槛让出清楚边缘；原稿RGB不改写、不用另一张生成图代替。

## 战斗行为

方向在出刀时固定，中心随角色移动；前摇 / 生效默认各0.12秒，高攻速读取实际Swing时长。每个固定模拟步合并经过的测量外沿，仍只查询一个填到中心的曲面，避免跳过短有效期或漏掉步间路径；F3只显示当前曲面，不叠画历史方块。

目标碰撞圆与曲面相交且没有地形遮挡时，由CombatEngine结算；同刀每目标最多一次，各玩家sourceId / attackId独立。前摇没有伤害，结束后最多0.12秒低亮余迹没有伤害。暂停冻结，冲刺 / 死亡取消，重开 / 切场景清理。

## 修改与复验

- 改整体大小：`content/attacks.ts` 的slash.range / 单位attackRange，图片与判定自动等比缩放。
- 改前摇 / 生效时间：slash.windup / slash.active，动画和测量相位共同映射实际时长。
- 改图片、裁剪窗口、支点或材质混帧：重新执行`pnpm measure:melee`，不得手改生成轮廓；`pnpm measure:melee --check`检查数据与测量来源一致。
- slash.arc只报告实测最大覆盖角，不参与圆形裁剪；不要用改arc的方法硬切弯曲刀光。
- 修改后重新构建Creator Web Desktop，再刷新8080。新TS资源的.meta由Creator导入生成。

验证包括：测量来源hash、原图窗口、同相位图像 / 曲线、贴身 / 中 / 远、曲线外但旧圆内拒绝、背面缺口、外沿、墙体、有效期进出、每刀一次、多玩家来源、暂停 / 取消 / 结束余迹。构建后运行test:hitboxes、test:melee及test:melee-alignment，并检查F3与实际光流叠图。真实联机延迟与四客户端GPU压力不属于本次修复。
