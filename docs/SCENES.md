# 营地、休息点与余烬交互

2026-10-19 起，玩法中的“增益”统一称为**余烬**。内部稳定 ID `PerkId / PERKS / perk:` 保留；余烬选择同时包含被动效果与可替换 Q/W/E/R 的主动技能。

## 当前体验

开始单人游戏或房主启动房间后，队伍进入可移动的启程营地。营地为独立的 24×20 遗迹平台，复用所选地图的环境主题，镜头仍跟随本地玩家。

1. 靠近中央余烬，按 **F** 打开三选一。每名玩家独立领取一次；初始余烬必须选择，才能出发。
2. 选择技能时再确认替换槽位；Esc 可暂时关闭面板，重开保留相同候选与待选技能，不重新抽取。
3. 前往出发点的地面集合圈。站在圈内即表示准备；离圈立即取消。全体活跃玩家都在圈内且关闭交互面板后，房主按 F 出发。单人玩家就是房主。
4. 战斗清场立即结算一次关卡金币，并进入可走动的 `cleared` 阶段。不会自动打开商店或余烬面板，也不会因为站在出口而自动跳关。
5. 如本关配置清场余烬，可在出口附近互动领取；之后队伍在出口集合，由房主按 F 进入下一段旅程。最终 Boss 关同样确认出口后才显示通关结果。
6. 配置了休息点的关卡，出口先通往休息点。靠近行商按 F 开店，购买 / 换装后按 Enter 或 Esc 离开商店，再在出发点集合。非初始余烬可选择跳过，离开场景后不能返回领取。

默认两张地图的配置相同：

| 地点 | 商人 | 余烬 |
| --- | --- | --- |
| 出生营地 | 无 | 首次必选，每人一次 |
| 第 1 关清场 | 无 | 可选 |
| 第 2 关之后的休息点 | 有 | 可选 |
| 第 3 关清场 | 无 | 可选 |
| 第 4 关之后的休息点 | 有 | 无 |
| 第 5 关清场 | 无 | 可选，出发点用于结束试炼 |

原有“开局商店 / 每关自动奖励 / 每关自动商店”已移除。初始金币仍为 160，清场金币仍为 100/120/140/160/180；本次没有调整装备与战斗数值。清场后倒地队友在存活队友附近以 30% 生命复起，参与集合；全队战斗中倒下仍然失败。离线玩家仍遵循房间暂停 / 房主跳过离线成员规则；跳过者不参与集合检查。

## 切换表现

营地、关卡和地图共用同一个 Cocos 主场景，图集在启动时统一加载，切换不重新下载资源。`render/SceneTransition.ts` 在新场景的首个显示帧遮黑 0.04 秒，再用 0.18 秒淡出；总计约 0.22 秒，没有进度条或额外等待。

表现按 mapId、scene.id、首页 / 游戏身份及本地世界实例代次识别切换，因此同一关的 F2 重测也能过渡；房间以房间码区分，tick 回退作为恢复的补充信号。实例代次只在本地适配器提供给显示层，不写进存档或联机协议。开关商店、余烬面板、暂停以及 fighting → cleared 不触发黑幕。初次首页沿用真实美术加载提示，加载失败提示不受此效果覆盖。

黑幕仅属于本地显示，使用 Cocos 帧时长推进；不使用战斗时间，也不修改 / 延迟 GameCommand、暂停房间或更改存档。暂停中切图仍能正常露出画面；快速切换用最新场景重新计时。`?debug=1` 的 `transition()` 提供只读诊断，`pnpm test:transitions` 检查实际 Creator 画面、面板例外、暂停与重测。

## 地点名称与入场标题

地点采用配置定义，共用 `content/locations.ts` 的 `LocationDefinition`，不需要各自创建 Cocos 场景类。`MapDefinition`、`LevelDefinition` 和 `RestStop` 继承这份接口，出生营地也必须满足它：

```ts
interface LocationDefinition {
  name: string;       // 必填：浮现的地点名称，也供 HUD / 交互面板显示
  subtitle?: string;  // 可选：路线名、营地用途等说明
}
```

- 地图 / 战斗关卡：编辑 `content/maps.ts`，如 `level('ember-1', {name: '余烬庭院·一', subtitle: '苔阶巡径'}, ...)`。
- 出生营地：编辑 `content/scenes.ts` 的 `JOURNEYS.ember.camp`，目前为 `{name: '余烬庭院', subtitle: '启程营地'}`。
- 休息点：编辑 `JOURNEYS.ember.rests[2]` 等配置中的 `name / subtitle`；新增休息点同样必须提供名称。

两图共 16 个可进入地点均已配置。名称可完全自定义，不要求按数字命名。`validateContent` 在启动和测试时拒绝缺失 / 空白名称；副标题可省略，主标题会居中。改名不改 `MapId / level.id / camp:N / level:N`，不会丢失存档、余烬领取或购物进度。配置属于源码，改完需重新构建或编辑器预览。

`sceneLocation` 统一解析配置 → `SceneSnapshot.name / subtitle` → 每玩家的 `PlayerView` → `SceneTransition`。标题在 0.22 秒黑幕之后淡入 0.24 秒、停留 1.45 秒、淡出 0.45 秒；显示期间仍可移动和战斗，无点击拦截。进入新地点、同关重测和恢复重进会重新显示；开关商店 / 余烬、清场、暂停不会触发。个人面板、暂停、开发面板和结算页会隐藏标题，计时继续，不在关闭面板后补播过期标题。快速跳关仅保留最新地点；首页不显示入场标题。

只读 `transition().title` 可查看当前文字、透明度和计时。标题不进入存档；快照只增加可选副标题，房间协议仍为 ember-coop-6，恢复格式仍为 v4。

## 扩展入口

`EmberDemo/assets/scripts/ember/content/scenes.ts` 维护 `JOURNEYS`、`CAMP`、营地地形和交互点定义。地图敌群与每关起终点仍在 `content/maps.ts`。

```ts
// 第 3 关出口后插入休息点，既有商人也有余烬。
JOURNEYS.ember.rests = {
  3: {name: '余烬庭院·林间歇所', subtitle: '整备与休息', merchant: true, ember: true},
};
// 只在第 2、5 关清空后生成余烬。
JOURNEYS.ember.clearEmbers = [2, 5];
```

上述示例用于说明配置形状；实际修改注册表源码，不在运行中写共享配置。`rests` 键为“已经完成的关卡”，必须小于总关卡数；可独立配置 merchant/ember，允许只有集合点的休息区域。清场余烬目前在本关出口 X 轴左侧 3.5 格；改位置同时验证可达性、交互范围与地图障碍。`validateContent` 验证配置、交互点可达性和范围；复杂新地形可扩展布局数据，不在 GameWorld 按 MapId 加分支。

添加全新交互类型时依次扩展：`InteractionKind / InteractionDefinition` → 逻辑命令处理 → `SceneSnapshot` → `InteractionView` 与 HUD → 恢复校验与测试。角色、商人、余烬和出发点使用相同的世界坐标与投影；商人/余烬是非战斗交互物，不占 Actor，不用贴图距离判断互动。

## 状态与权限

- 全局 `GameWorld.phase`：ready / camp / fighting / cleared / victory / defeat。
- 玩家 `PlayerState.panel`：shop / reward / undefined。`WorldSnapshot.phase` 为本地面板或全局阶段，`stagePhase` 始终保留真实全局阶段。不要根据本地主机的面板冻结整个队伍。
- 玩家 `claimed`：稳定交互点 ID 列表，如 `camp:0:ember`、`level:1:ember`。当前候选、pendingSkill 与 interactionId 持久保存。领取时清空候选，不重新发金币。
- `SceneSystem.inspectScene` 根据每个人的当前世界位置、active/alive、面板和初始领取状态计算集合条件；`Interact` 命令再次检查。客户端不传“已准备”或“我是房主”。房主身份来自 RoomTransport 的房间信息，恢复换房主后同步更新。
- 交互只在 camp / cleared 且存活、未暂停时接受。购物只在实际打开的商人面板里接受。面板打开清除本人的路径、按住普攻和移动输入；其他队友继续活动。安全场景禁用攻击和技能，碰撞移动仍使用 Pathfinder。
- 营地与战斗地形各自缓存导航 / EnemySystem；切换时清理瞬态动作、弹体和输入。清场与营地入口移除减速、持续伤害、护盾及临时属性 / 战斗效果，保留永久属性与构筑，不给存活玩家额外治疗；避免战斗时钟停下后临时效果无限持续。CollisionWorld 的 terrain 跟随地形切换，CombatEngine 继续使用同一碰撞实例。

## 恢复与联机

房间协议 **ember-coop-6**，恢复点 **v4**。旧 v1–v3 存档明确拒绝，因为旧阶段和自动奖励语义不能直接映射。客户端与中转需一起更新。开发者配置仍为 v2，新增可选 `entry: 'combat' | 'camp'`，旧开发者预设默认战斗。

营地、休息点和清场后的领取、候选、购物及阶段变更都会保存稳定恢复点。安全场景移动不每帧保存，恢复可能回到最近一次交互的位置；战斗中仍恢复至本关起点，不保存战斗中间帧。仅服务器确认的恢复点保证跨房间续玩；断线瞬间尚未确认的操作仍可能回退。

`PlayerView` 必须携带每个人的 phase 与 scene，避免把房主打开的奖励页或房主的已领取状态显示给队友。集合条件不保存成永久 ready 标记，而是恢复后按位置重新计算。

## 开发验证

F2 → 关卡 / 工具 → **场景：营地 / 休息点**。关卡选项切换为 1/3/5，分别代表第 1 关前的出生营地、第 3 关前与第 5 关前的休息点。应用才创建测试世界；普通局不获得测试开关。战斗测试世界依旧清场留在原地，便于刷怪。

- `pnpm check`：核心、Cocos、工具类型与逻辑 / 真实中转测试。
- `pnpm test:campaign`：正常命令移动、互动、奖励、购买、战斗与出发，两图各五关；不改 HP/伤害 / 冷却。
- `pnpm test:scenes`：实际 Creator 页面中走到余烬和出发点，验证双操作、个人面板、休息点交易与回到战斗。脚本内明确区分正常出生流程与 F2 的休息点定向验证。
- `pnpm test:locations`：正常开始的入场标题逐帧检查、全部 16 个地点的 F2 配置核对、两种窗口尺寸与重测 / 面板 / 首页生命周期；`test:multiplayer` 同时检查房主、队友入营地与第一关的标题。

`tests/helpers/scenes.ts` 仅用于隔离战斗/装备单元测试：显式种入已领取首个余烬且不附加随机被动的 fixture，避免无关奖励改变伤害断言。真实开局路径由 scenes.test、transport.test 和浏览器脚本覆盖，不能将 fixture 当作生产快速开局接口。
