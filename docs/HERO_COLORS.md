# 主角配色：同一套整身动画

2026-10-21。用户确认采用[Q版复燃者](../art-source/rekindled-chibi-v1/README.md)，并要求多人可切换人物颜色。当前已接入[粗像素Q版完整动作](../art-source/chibi-runtime-v1/README.md)，六种配色直接复用同一套整身图集。

## 使用

点击画面左上角“人物配色”，选择灰烬、苔青、霜蓝、暗绯、赭金或暮紫，点击“完成配色”。首页、营地、战斗和联机等待房间均可使用；打开时会停止本人的移动输入，多人世界继续运行。房主或中转不可用时禁用选择，避免假装已同步。

每人独立选择，允许同色；新成员默认按席位分配不同颜色。脚下圆环同步配色，本人圆环稍粗，颜色不影响属性、碰撞或装备。单人选择记在本机，读档以存档人物颜色为准；多人重连 / 重新开房读取恢复点中的各自颜色。

## 技术落点

- `content/hero-palettes.ts`：稳定 `HeroPaletteId`、中文名称、圆环色及衣料目标色。新增一种颜色只改此表，无需新增 PNG。
- `platform/protocol.ts` 的 `SetHeroPalette`：只传配色 ID，不接受客户端指定其他玩家身份或任意材质路径。`GameWorld.players` 各自保存 `paletteId`，由 `WorldSnapshot.party` 输出。
- `ArtLibrary`：加载一个 `resources/effects/hero-palette.effect`，每组配色缓存一份 Material，所有角色共用原图与 SpriteFrame。`HeroSprite` 切换材质，不修改共享纹理，不逐帧创建材质。
- Shader：对源图的冷灰紫衣料色阶进行重映射，保留亮度、透明度和深色轮廓；暖色皮肤、腰带及火光不进入此色域。受击高亮在换色后叠加，所有朝向 / 动作共用这一步。
- 联机使用 `ember-coop-9`。换色是独立的外观命令，在等待房间和暂停界面也可发送；中转按连接身份转发，房主验证并更新。恢复点保持 v5，新增 `paletteId`；旧 v4/v5 缺省字段按席位补默认，非法颜色拒绝。已存储的6/7/8版房间可迁移恢复，在线客户端和中转必须同版。
- 战斗中换色仅修改已有恢复点的配色元数据并保存，不把当前位置、伤害、金币或随机状态保存成战斗中途进度。

## 新Q版资源的制作契约

只制作一套整身帧。可染色的衣料使用独占的冷灰紫色阶；皮肤、阴影脸、腰带和余火不复用该色域。保持跨动作同一色板，深轮廓不染色。以灰烬 / 苔青 / 霜蓝 / 暗绯四组对照检查，不只看原色。

当前Q版PNG没有语义遮罩，Shader按冷紫色域识别。实际菜单六配色和移动帧已检查，暖色尸肤、腰带和余火保持；深色衣褶和脸部交界仍有同色重叠的可能，不能称为精确逐像素分区。后续若需要更严格分区，可增加一张与动画布局一致的共享染色遮罩。即使使用遮罩，也不需要每种颜色各生成一套贴图。

保持无血、无发、无五官与少量余火，不靠全身染红 / 染蓝区别玩家。此能力是固定角色的配色选择，不恢复装备换皮、纸娃娃挂点或衣物款式切换。

## 验证

逻辑验证覆盖玩家隔离、非法颜色、旧存档补缺省、跨波恢复、战斗恢复点不前移与本机偏好。实际 Creator 构建及双浏览器操作验证见 `reports/hero-palettes/`；Q版动作与配色的本轮验证见 `reports/chibi-hero/`；四人特效性能需单独验收。
