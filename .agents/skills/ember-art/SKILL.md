## 保持的设计约束

- 黑暗像素奇幻、清楚像素簇、受控色板和硬边色阶。用灰烬、死亡痕迹与局部余火表达氛围，地面和单位保持可辨明度；不把画面整体压黑。血迹可用于相应世界 / 敌人设计，但基础主角没有血。旧 PNG / Graphics 是运行时与技术参考，不自动成为新方向的风格样张。
- 基础人物采用已选Q版的大圆头、宽短躯干与短粗四肢，不沿用03版修长体型。多人衣料换色共用一套整身帧，预留独占冷灰紫色阶，避免皮肤 / 阴影脸共用；见[配色契约](../../../docs/HERO_COLORS.md)。当前Q版完整动画与六种配色已接入chibi-v1；精确网格、限色与步态精修仍需按实际画面验证。
- 用户随后要求更粗像素：身份参考chibi-v1，细节密度参考[粗像素修订](../../../art-source/rekindled-chibi-v2/README.md)。采用明显大色块、简化手脚和衣褶，不恢复细密头皮 / 布纹，不用模糊或整图马赛克替代造型简化；概念板不代表严格网格 / 限色已验收。
- 基础人物共同表达被残火点燃的无名死者，无固定职业。保持无血、无发、无五官阴影面孔，不以兜帽或面具替代；灰白干枯身体与少量干燥余火可读。玩家每帧绘制一个完整身体，头、躯干和四肢自然相连，不再做纸娃娃或独立关节部件；装备只提供属性 / 被动与UI图标，不改变人物贴图。
- 怪物和道具保持身份、肢体数量、材质、轮廓、配色与朝向一致。主角五个绘制视角加三镜像覆盖八方向；怪物仍以三分之四朝向加左右镜像为主。不能把主角方向支持写成所有素材均已完成。
- 可行走地面安静，装饰集中在边缘。敌人预警、单位和攻击方向优先于装饰及海克斯闪光。
- 环境采用斜俯视物件 + 等比例地面的2.5D表现，以顶面 / 侧面、独立阴影和遮挡体现体积。地面不压纵深、不随远近缩放，圆形范围保持圆形；不得为适配美术改变移动速度或判定。占地、锚点、分层和验收以[环境规则](../../../docs/ART_DIRECTION.md#环境视角与地面度量)为准，不套用旧2:1菱形地面模板。
- 本体动作与技能刀光、弹体、爆炸、地面圈分开。角色余火或怪物固有标记可以作为身份设计，技能变化仍使用独立表现层。血迹与飞溅不能覆盖危险范围或伪装成规则预警圈。跑步独立设计接地 / 压低 / 蹬伸 / 腾空，保留固定地面基准与身体起伏，不能把行走提速或少数姿势板宣称为完整跑步循环。
- 图片、动画和地面锚点不定义伤害、碰撞或实际位移。模拟时钟 / CollisionWorld 是判定来源。
- 默认近战按[实测原稿曲线](../../../docs/design/BASIC_MELEE_VFX.md)显示和命中：测量工具复现材质混帧，以alpha≥0.1提取外沿，填到人物中心保留贴身命中。图片与判定共用同一测量相位及统一尺度，不再固定180°裁剪，也不叠加任意圆形外沿。改原图 / 窗口 / 混帧后重新生成melee-outline并复核测量报告；原稿RGB保持不变。
- 所有攻击 / 技能特效必须轮廓清晰，与实际生效范围、方向和时段一致，覆盖玩家、敌人及触发效果；不能只检查预警或以装饰层名义误导边界。环境 / UI / 纯装饰特效不受这条硬边与判定对齐要求限制。制作与验收遵循[判定一致性](../../../docs/PIXEL_VFX.md#攻击与技能特效的判定一致性)。

## 形成具体制作规格

先从现有内容推导能确定的字段，只有缺失信息确实影响结果且无法推断时才询问：

- 对象 ID、用途、交付层级、新增还是替换，以及哪些现有对象可复用。
- 参考图各自角色：身份、风格、布局或待编辑目标；先实际查看本地图片，不声称看过未加载的文件。
- 源逻辑画布、共享色板、网格原点、源 texel 显示倍率、游戏内显示尺度、朝向、图集布局和透明要求；动画另写帧序、FPS、循环性、关键姿势和预期播放时长。
- 玩家写完整身体的帧序、五绘制方向 / 三镜像、固定比例与共同地面基准；每帧姿势可以起伏，但不能按最低像素贴底或按包围盒缩放。装备任务只制作物品图标。
- 环境写地面 / 直立分类、世界占地与显示尺寸、地面锚点、朝向、遮挡和独立阴影；说明源图是否已按屏幕方向绘制，避免重复旋转。锚点与碰撞说明放在制作记录，不能画进生产PNG。
- 攻击 / 技能写明实际判定形状与参数来源、预警 / 生效 / 结束相位、旋转原点和投影；有安全空洞或动态范围时单独标注。无独立判定的命中反馈注明事件锚点。先明确这些约束再生成，不能把概念图当作已校准的范围图。

修复现有运行资产时保留相关屏幕占比与动作契约。重设计概念可探索新比例，转入生产时要单独完成全动作尺寸、帧间比例和锚点方案。丰富度优先来自轮廓、重心、关键姿、材质色块，不能只堆纹理或增加整图摇摆。源画布和倍率依实际镜头下的像素试样确定；概念板的游戏尺度小图仅是示意，不能冒充 Creator 截图或可运行动画。

## 选择工具与制作路线

1. **位图生成 / 编辑**：使用环境提供的内置 `image_gen`，如有 `imagegen` skill，遵循其当前工具用法。透明资产明确请求真实 alpha；本地编辑目标先查看。保留实际返回的输出，不猜文件路径、模型版本、种子或未暴露参数。
2. **已有代码表现**：现有 Graphics 特效、HeroSprite 播放与地面锚点问题可以直接修改相关代码；用户需要贴图时不能用 SVG / Canvas 占位图冒充生成素材。
3. **序列帧**：以同一个身份参考制作单动作帧组，重点检查关键姿势；图集布局和图片尺寸以实际测量为准。玩家采用完整身体逐帧绘制，不重新拆成头、躯干和四肢；更换装备不得选择另一套人物图集。
4. **图生视频**：只有工具可用且用户已授权该路线时使用。无视频能力就使用位图姿势帧或交付明确标注的制作规格；若视频是用户指定的必需交付，报告缺少能力，不能冒称生成成功。不要自动注册外部服务、购买套餐、上传到新服务或切到 API 计费。
5. **加工**：当前 `scripts/inspect-art.py` 只分析图片并生成数据，不编辑 PNG。图片编辑仍使用环境规定的编辑工具；不要偷偷用 Python 重绘 / 抠图替代。只有用户明确要求或当前工具规则允许的抽帧、裁切、拼图等加工才采用相应工具，并保留源文件与空间变换记录。

不能用“先得到用户人工批准”阻塞已明确授权的普通素材制作；使用现有认可素材作为参考，代理自行完成技术检查。不得将代理验收记录成用户已批准新的风格。重复失败时缩小到一个对象、一个动作，记录具体缺陷并修正；不要持续无界重试、扩展付费调用或把不合格成品标为通过。

## 生成、检查与接入

先完成一个代表对象的闭环再批量制作同系列，用户明确要求批量时保留每个请求资产的交付清单。每次修订围绕一个明确问题，保持身份、布局、已通过部件等不变量。

在 `art-source/<本次资产批次>/` 保存 Prompt、参考路径、源输出及制作记录，候选与运行时文件分开；生成工具返回文件后复制选中结果到工作区。默认使用版本化候选，不覆盖未要求替换的资源。视频 / 高分辨率中间件的 Git 存储按实际大小决定，不全量盲目提交，也不丢失来源索引。

按 [接入与验收](references/integration.md) 检查源像素网格 / 色板、alpha、轮廓、动作一致性、整身锚点、最近邻与实际显示倍率、多效果画面；粒子按 PIXEL_VFX 记录可读性及性能证据。图集自动分析只验证可测项目，不证明美术可用。只有用户要求接入或任务本身包含接入时，才将通过的候选接入 Cocos。
