# Ember 美术资源制作

将用户指定的美术任务推进到对应交付层级：设计 / Prompt、素材制作，或素材接入游戏。只审阅时不启动生成；只要预览时不替换运行时资源；要求接入时完成配置、构建和画面验证。沿用用户已授权的范围，不在每个制作阶段重复等待确认。

## 定位当前工程

从当前工作目录定位 Project Ember 根目录，检查 `git status --short`、`AGENTS.md`、`EmberDemo/package.json`。本 skill 随仓库保存在 `.agents/skills/ember-art/`；不要将本机绝对路径写进资源引用。若当前不是 Ember 工程，先定位用户指定工程，不给别的项目套用这些配置。

阅读根目录下 `docs/ART_DIRECTION.md` 与 `docs/ART_PIPELINE.md`。它们分别维护视觉标准和实际接入方式；用户当次明确要求可以调整标准。旧草案 `CODEX_AI_ART_ANIMATION_RULES.md` 的取舍见 `docs/ART_ANIMATION_REVIEW.md`，不要恢复其中已被纠正的风格或未实现能力。

按任务加载资料，不必每次阅读全部文件：

| 任务 | 需要阅读 |
| --- | --- |
| 生成贴图、部件、装备、地图或特效 | [Prompt 模板](references/prompts.md) 的相关类型；实际参考 PNG |

| 导入、切片、换装、运行验证与交付 | [接入与验收](references/integration.md)；对应配置和渲染器 |

这些源码文件位于 `EmberDemo/assets/scripts/ember/`。配置与实现发生变化时，以实际代码为准，同步修订有关参考，不能按 skill 中的历史数值强行改回旧版本。

## 保持的设计约束

- 明亮自然遗迹、非像素卡通、大形状、少量色块、柔和分面。参考图只取氛围；禁止为了更精美堆叠雕花、碎叶、碎石和持续强光。
- 基础人物无固定职业，用普通短发、简单五官与中性短衣；职业倾向由可替换装备体现。混搭也需保持相同比例、视角和关节连接。
- 怪物和道具保持身份、肢体数量、材质、主轮廓、配色与朝向一致。现有单个三分之四朝向加左右镜像，不默认生成四 / 八方向或整张职业人物来替换纸娃娃。
- 可行走地面安静，装饰集中在边缘。敌人预警、单位和攻击方向优先于装饰及海克斯闪光。
- 本体动作与技能刀光、弹体、爆炸、地面圈分开。已有金色面部标志等身份特征可以保留，不能把“没有战斗特效”误解为抹掉主体特征。
- 图片、动画和装备挂点不定义伤害、碰撞或实际位移。模拟时钟 / CollisionWorld 是判定来源。

## 形成具体制作规格

先从现有内容推导能确定的字段，只有缺失信息确实影响结果且无法推断时才询问：

- 对象 ID、用途、交付层级、新增还是替换，以及哪些现有对象可复用。
- 参考图各自角色：身份、风格、布局或待编辑目标；先实际查看本地图片，不声称看过未加载的文件。
- 游戏内显示尺度、朝向、图集布局、透明要求；动画另写帧序、FPS、循环性、关键姿势和预期播放时长。
- 纸娃娃写部件、握点与遮挡；新动作写画布 / pivot 策略及现有渲染器是否兼容。

已有同类对象的尺度与动作布局优先复用。真正需要新能力时明确接入改动，不能将未来设想写成现有配置开关。

## 选择工具与制作路线

1. **位图生成 / 编辑**：使用环境提供的内置 `image_gen`，如有 `imagegen` skill，遵循其当前工具用法。透明资产明确请求真实 alpha；本地编辑目标先查看。保留实际返回的输出，不猜文件路径、模型版本、种子或未暴露参数。
2. **已有代码表现**：现有 Graphics 特效、HeroRig 动作和纯挂点问题可以直接修改相关代码；用户需要贴图时不能用 SVG / Canvas 占位图冒充生成素材。
3. **序列帧**：以同一个身份参考制作单动作帧组，重点检查关键姿势；图集布局和图片尺寸以实际测量为准。纸娃娃动画优先沿用现有部件，不重新生成整个人物每一帧。
4. **图生视频**：只有工具可用且用户已授权该路线时使用。无视频能力就使用位图姿势帧或交付明确标注的制作规格；若视频是用户指定的必需交付，报告缺少能力，不能冒称生成成功。不要自动注册外部服务、购买套餐、上传到新服务或切到 API 计费。
5. **加工**：当前 `scripts/inspect-art.py` 只分析图片并生成数据，不编辑 PNG。图片编辑仍使用环境规定的编辑工具；不要偷偷用 Python 重绘 / 抠图替代。只有用户明确要求或当前工具规则允许的抽帧、裁切、拼图等加工才采用相应工具，并保留源文件与空间变换记录。

不能用“先得到用户人工批准”阻塞已明确授权的普通素材制作；使用现有认可素材作为参考，代理自行完成技术检查。不得将代理验收记录成用户已批准新的风格。重复失败时缩小到一个对象、一个动作，记录具体缺陷并修正；不要持续无界重试、扩展付费调用或把不合格成品标为通过。

## 生成、检查与接入

先完成一个代表对象的闭环再批量制作同系列，用户明确要求批量时保留每个请求资产的交付清单。每次修订围绕一个明确问题，保持身份、布局、已通过部件等不变量。

在 `art-source/<本次资产批次>/` 保存 Prompt、参考路径、源输出及制作记录，候选与运行时文件分开；生成工具返回文件后复制选中结果到工作区。默认使用版本化候选，不覆盖未要求替换的资源。视频 / 高分辨率中间件的 Git 存储按实际大小决定，不全量盲目提交，也不丢失来源索引。

按 [接入与验收](references/integration.md) 检查 alpha、轮廓、动作一致性、挂点、实际尺寸和多效果画面。图集自动分析只验证可测项目，不证明美术可用。只有用户要求接入或任务本身包含接入时，才将通过的候选接入 Cocos。
