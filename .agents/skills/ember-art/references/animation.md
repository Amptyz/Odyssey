# 动画与坐标契约

本文件只在制作或修复动画、改变图集布局时读取。以下是建立 skill 时的代码基线，实际任务须检查当前实现。

## 当前播放器能力

源码根目录为 `EmberDemo/assets/scripts/ember/`：

| 文件 | 实际职责与限制 |
| --- | --- |
| `content/animation.ts` | `AnimationClips` 每种状态只有 frames / fps / loop，均匀播放；无逐帧时长、方向表、事件数组 |
| `render/AnimatedUnit.ts` | 怪物序列帧、左右镜像、固定像素比例、底边锚点；死亡 0.9 秒内淡出 |
| `render/HeroRig.ts` | 玩家六部件的程序动作和装备挂点，不是整人序列帧或 Spine |
| `render/ArtLibrary.ts` | 从 `art/living-ruins/<AtlasId>` 加载；读取 TS 图集区域，没有任意 JSON manifest 导入器 |
| `scripts/inspect-art.py`（仓库根目录） | 寻找近网格透明切线、按 alpha 边界裁切区域，生成 TS 和检查报告，不改像素 |

现有怪物图集为 4×4：idle 0–3 / walk 4–7 / attack 8–11 / hurt 12 / death 13–15；cast 复用 attack。FPS 分别为 4 / 9 / 9 / 8 / 4，cast 为 7；仅 idle / walk 循环。不是固定的行业规格，改变布局需要同步生成器和配置。

`motionPose` 还有状态时间窗口：受击约 0.18 秒、出手后的 attack / cast 约 0.45 秒；windup 期间将 attack age 固定为 0.08 秒。仅增加帧数并不能让动作播完，例如 12 帧 / 12 FPS 需要约 1 秒的播放时间。新长动作要检查状态选择、受击打断、死亡淡出和战斗前摇的映射；不要只改 FPS，也不要为配合美术擅自改变伤害时刻。当前 cast 的名义剪辑时长也长于出手显示窗口，验收时需观察末帧是否真正出现。

## 生成时锁定什么

身份（轮廓、肢体、体型、武器、配色）、视角、单一朝向、镜头、身体尺度和全动作留白应稳定。姿势造成的宽高变化是动作，不能强行消除。没有根位移的行走在原地完成，世界移动由模拟层应用；攻击可倾斜或下蹲，但不要穿过画布或忽然换手。

每个动作独立制作，以同一身份图为参照；“独立制作”不要求每一帧都重新调用模型。关键姿势可在同一帧组生成。准备、蓄力、出手、恢复是语义，不强制每阶段恰占一帧或等时。

循环检查首尾姿态和节奏；只有末帧确实重复首帧且造成停顿时才删除。攻击恢复到待机是合理的，不能将 one-shot 误解为“不许回到准备姿势”；它表示只播放一次。死亡不恢复站立。已存在的武器和面部特征要保留，“不新增眼睛 / 武器”不等于删除原有设计。

## 两种空间策略不可混用

### A. 当前按底边贴地的序列帧

生成器以 alpha > 24 的区域估算边界并留少量边距；`ArtFrame.rect` 使用图集左上角像素坐标，`pivot` 是裁切区内像素坐标，不是 Cocos 归一化坐标。当前生成值为 `[原格中心X - 裁切X, 裁切高度]`。

AnimatedUnit 只消费 pivot X，将 Cocos anchor Y 固定设为 0；每帧图像底边贴到单位地面位置，不能表达任意 Y pivot。它保持固定像素比例，没有把每帧缩放到同样宽高，但会抹去画布内整体向上的位移。

使用现有布局制作贴地动作时，验证脚、低垂武器、死亡散落物是否改变最低像素，造成身体抖动。alpha bbox 不是人体尺度，也不一定是脚底。底边对齐通过检查不代表保留了原始空间运动。

### B. 保留画布的动画来源

对于锁定镜头的视频或已统一画布的帧：保持原画布、原始坐标、共同缩放和共同地面锚点。可以用整个动作的联合边界统一裁切并记下偏移，不逐帧居中、拉伸或强贴脚底；跨 idle / walk / attack 还要保留同一个角色坐标基准，不能各自裁成不同中心后丢弃偏移。

这条路线**不是当前自动导入能力**。接入前需为该资产实现并验证一种明确方案：保存完整固定帧画布及共同 pivot，或保存裁切后的原画布尺寸、偏移与共同 pivot 并在渲染中恢复。生成器也要能够保留这些数据；不能再让默认裁边覆盖它们。改动仅针对需要的新模式，保留旧素材的兼容性。

纸娃娃的 `anchor / grip` 使用图片左下角为原点的归一化坐标。与图集左上角像素 pivot 转换时写清原点、单位和裁切偏移；不要把草案 `[0.5,1.0]` 当作所有系统通用的“脚底”。

## 位图姿势帧路线

1. 对照已接入对象确认身份与基础姿势，设计极值和过渡，不从复杂场景海报直接生成多种动作。
2. 一个动作一个帧组，明确帧序 / 布局 / 留白。输出后测量实际尺寸，检查主体是否跨格。
3. 独立生成的 clip 若整体尺度不一致，按相同姿态下的身体部位评估；不能按含武器、树角的总 bbox 给每帧分别缩放。
4. 错肢体、变脸、换方向要修正或重生成。裁切 / 归一化不能补救身份变化。
5. 选择 A 或 B 的接入策略，真实预览动作循环、转接与镜像后才接入。

## 可选图生视频路线

先核对工具是否可用、用户是否已授权该服务与调用；不要照外部文章硬编码供应商、模型名、4 秒或 720p。静态 image_gen 不能产生真实视频。

- 用动作合适的起始姿势和同一身份参考，固定镜头、单一朝向、无场景与战斗特效。模型不支持 alpha 才考虑与主体不冲突的纯色底。
- 在支持并已获准的视频加工工具中，按源时间顺序抽取所有帧，记录时间戳和源帧索引，制作带编号概览后选择动作关键帧。
- 原始视频时长、采样帧数、游戏播放 FPS 是三件事。若不均匀选帧却以等 FPS 播放，会改变动作节奏；当前播放器不支持逐帧时长，需重新安排采样或单独扩展播放器。
- 保留画布；原视频本身缩放、漂移、换向时先修源，不用逐帧平移掩盖错误。
- 仅在工具支持且测试有效时对循环指定相同首尾图，不把它当成普遍保证；one-shot 不强制通过视频插值回弹到起点。
- alpha 清理检查连续多帧轮廓闪烁、叶片 / 武器尖缺失和溢色。只声明 RGBA 还不够，要检查透明像素及实际边缘。

## 制作记录与运行时数据

每批记录源文件、身份参考、实际工具 / 暴露的模型信息、最终 Prompt、实际尺寸、帧序、动作类型、FPS / loop、空间策略、锚点原点与单位、裁切 / 采样变换及 QA 结果。未知模型 / seed 写 unknown，不虚构。

可用批次内 `production.json` 保存这些制作信息，格式按素材需要取舍；它不会被游戏自动读取。运行时事实仍在 `art-manifest.ts`、`appearances.ts` 和 `animation.ts`。视觉接触点可记录用于验收，但没有现成的 `contact_visual` 事件消费器，也不能借它触发伤害。
